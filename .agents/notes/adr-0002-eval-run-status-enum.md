# ADR 0002 · 评测任务状态枚举与「部分成功」语义

[English](adr-0002-eval-run-status-enum.en.md) | 中文

- 状态：已采纳
- 日期：2026-11-11
- 适用 issue：m5-16（#144，评测列表统计筛选）、m5-17（#145，评测详情独立路由）
- 设计依据：`plans/m1-02-fullstack-design/06-execution-and-resource-pools.md` §2

## 背景

评测列表与详情需要展示同一套任务状态，但此前没有单独记录状态枚举的来源。列表页曾只渲染「运行中 / 失败 / 已完成 / 已取消」，而终态实际还有「部分成功」；前端若按用例计数自行推断状态，会出现同一批用例在列表与详情显示不同结论的风险。

「部分成功」的定义是：全部逻辑用例已收口，但至少一个用例失败、超时或取消，同时仍有可用结果。它不能被折叠为「失败」（结果仍可消费），也不能被折叠为「已完成」（并非全量成功）。

## 决策

后端 `EVAL_RUN_STATUSES` 是状态的唯一事实源，枚举如下：

| 状态 | 含义 | 终态 |
|---|---|---|
| `preparing` | 准备启动配置 | 否 |
| `queued` | 排队等待容量/派发 | 否 |
| `running` | 用例执行中 | 否 |
| `finalizing` | 收口聚合中 | 否 |
| `completed` | 全部逻辑用例成功收口 | 是 |
| `partial` | 全部逻辑用例收口，至少一个失败/超时/取消，仍有可用结果 | 是 |
| `failed` | 终态判定为失败（无可消费结果或调度失败） | 是 |
| `pausing_budget` | 预算用尽，正在暂停收口 | 否 |
| `paused_budget` | 预算暂停，等待增加预算 | 否 |
| `cancelling` | 取消请求处理中 | 否 |
| `cancelled` | 已取消 | 是 |

规则：

1. 状态由控制面写入，前端只按枚举渲染标签，不根据用例成功/失败数拼装新状态。
2. 终态集合为 `completed / partial / failed / cancelled`；其余为活动态，列表的「运行中」统计卡与自动刷新都按活动态判断。
3. `partial` 与 `failed` 的判定边界属于执行收口逻辑，列表查询不得重算；列表只读取 `eval_run.status`。
4. 列表筛选的 `status` 参数只接受上述枚举值，未知值返回 `422 evaluation_invalid`。
5. 列表的解决率按已评分用例（`resolved / (resolved + unresolved)`）聚合，未评分用例不计入分母；前端只格式化服务端结果。
6. 修改枚举或终态集合时，必须同时更新本 ADR、后端枚举与前端 `web/src/utils/evalStatus.ts`；不新增迁移，状态约束已由既有 `CheckConstraint` 承载。

## 影响

- m5-16 的列表统计卡、状态筛选与「部分成功」展示都以本 ADR 为准。
- m5-17 的详情页头部统计与状态堆叠进度条复用同一枚举和终态集合，不另立状态。
- 前端共享映射集中在 `web/src/utils/evalStatus.ts`，列表、详情和总览标签由它派生，避免各页各写一套。
