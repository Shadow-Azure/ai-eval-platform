# ADR 0001 · 数据集归入「评测」导航分组

[English](adr-0001-dataset-index-navigation.en.md) | 中文

- 状态：已接受
- 日期：2026-11-11
- 关联 issue：#141（M5-13 数据集目录适配器卡片目录与筛选分页）
- 决策者：本 issue 实现者；依据 `plans/m1-02-fullstack-design/02-prototype-and-interactions.md`

## 背景

原型与前端设计把数据集视为评测资产：`plans/m1-02-fullstack-design/02-prototype-and-interactions.md` §1 的侧边栏结构明确把「数据集」放在「评测」分组下（评测任务、数据集），「配置」分组只包含 Agent 资产、模型凭据与资源池。2026-11-11 的 UI 与原型对比发现线上把「数据集」移到了「配置」分组，导致信息架构与设计基线不一致，并让「评测」分组失去资产入口。

## 决策

恢复设计基线：数据集回到「评测」分组，与评测任务、发起评测并列；「配置」分组只保留 Agent 资产、模型凭据和资源池。侧边栏与页面面包屑使用同一分组名称，避免导航与页内层级互相矛盾。

数据集目录页本身仍然是配置型入口（导入新版本、查看适配器规范），但其信息架构归属按「评测资产」处理；这不改变任何 API 或权限边界。

## 影响

- `web/src/app/nav.ts` 的导航分组与面包屑改为「评测 / 数据集」「评测 / 导入数据集」「评测 / 数据集详情」。
- 数据集目录页的页眉不再使用 `Configuration · Datasets`，改为 `Dataset catalog`，与原型一致。
- 不新增权限、路由或后端契约；仅有导航归属变化。
- 后续新增数据集类型仍通过后端适配器注册表扩展，目录卡片读取注册表元数据。

## 未采纳的方案

- **保留「配置」分组**：与已定稿设计冲突，且会把评测资产入口与模型/资源等基础设施配置混在一起；若产品确实要改，需要新的设计文档修订，而不是由实现侧默认保留。
- **同时出现在两个分组**：同一路由在两个分组重复出现会增加导航噪声，也不符合原型的单一归属。
