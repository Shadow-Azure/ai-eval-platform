## Background

- The platform supports static asset sources scanned from `skills/` (e.g. Superpowers), but OpenSpec/CodeSpec repositories are the CLI itself: the agent workflow is generated by `openspec init/update` at runtime, so the repository contains no SKILL.md or commands.
- A production scan of `chenmr0/OpenSpec-cn` (the CLI source) returns 0 assets; the upstream `Fission-AI/OpenSpec` exposes 12 scannable skills, but they declare `compatibility: Requires openspec CLI` and `allowed-tools: Bash(openspec:*)`.
- The platform only displays `runtime_prerequisites` on the asset source and scan results; the Runner neither installs nor executes them. The execution image has no `openspec`, and the sandbox network is restricted, so evaluation stops at the CLI call.
- Such “repository + CLI-generated commands” assets therefore cannot be configured, verified or loaded today; the asset source needs runtime-prerequisite configuration and a load test.

## Goals

- Let an asset source declare runtime prerequisites: CLI install command and init/generate command (OpenSpec/CodeSpec etc.), with optional runtime and version.
- Provide an isolated load test: install the CLI, run init/update, scan generated skills/commands, and return status, generated inventory and logs.
- Freeze the load-test result and prerequisite commands into the asset snapshot so evaluations can trace them.
- Validate at prepare/launch: block or clearly warn when prerequisites are missing or the load test has not passed; after passing, hand generated assets and prerequisite commands to the Runner.
- Have the Runner execute prerequisites in the sandbox and inject generated assets; failures expose a clear error, logs and a retry path.

## Acceptance

- Prototype: the asset-source wizard shows the “runtime prerequisites” configuration and load-test panel, and the asset card shows status and results (prototype reviewed first).
- Backend: asset-source save/scan/load-test state machine and snapshot fields; prepare returns a readable block when not passed.
- Runner: isolated install/init execution and generated-asset injection; failures expose logs and error codes.
- Frontend: asset source, evaluation wizard and evaluation config display and validation are complete; unconfigured sources keep current behavior.
- Tests: backend state machine/snapshot/prepare checks, Runner prerequisite execution and injection, web build; re-test in production with an OpenSpec repository.
