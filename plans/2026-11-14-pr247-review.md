## §0 结论

实现路径与设计文档一致：`eval_run.max_turns`（200 默认，1–1000）→ prepare 快照/identity →
create → shard manifest → task payload → Runner `MAX_TURNS`；前端 Step 3/Step 4/侧栏和任务详情展示。
检视发现 2 个 UI 缺口已修复，其余为可接受的设计取舍。

## §2 数据流核对

`PrepareRequest.max_turns` → `build_preparation` 校验/冻结 → snapshot/identity/summary →
`consume_preparation(max_turns)` → `EvalRun.max_turns` → manifest `max_turns` →
`runner/lib/task-payload` → `real-task` env `MAX_TURNS` → Claude Code `--max-turns`。

旧行：migration server default 200 + serialization/manifest 防御性回退 200。
