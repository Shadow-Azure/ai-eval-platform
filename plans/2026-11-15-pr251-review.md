# PR #251 检视：运行时镜像源顺序回退

- 对象：`Shadow-Azure/ai-eval-platform#251`
- 分支：`agent/m8-33/cli-asset-source-mode-a9667f560a40`
- 日期：2026-11-15

## §0 结论

实现符合 issue #250：manifest/tasks 冻结 `image_sources`，Runner 按源顺序重写并 pull，失败/超时/慢回退，全部失败 `image_unavailable`；无阻塞性缺陷。

## §1 发现与处理

| # | 发现 | 定性 | 处理 |
|---|---|---|---|
| F1 | 单源 180s，20 个源可能等 1 小时 | 风险 | 已加总预算 `REAL_TASK_IMAGE_RESOLVE_BUDGET_MS`（默认 300s），预算耗尽即停 |
| F2 | 全部源失败时原被归为 `runtime_error` | 可诊断性 | 已特判 `image_unavailable`，错误码保留到 shard 失败 |
| F3 | `image-sources.json` 写入 trace 目录 | 观测 | 记录尝试链；放在 trace 便于下载 |
| F4 | 无 sources 时不做解析 | 兼容 | 保持旧行为；只有配置源才启用 fallback |
| F5 | 显式 registry 镜像也会追加 source 前缀 | 边界 | 先原样尝试，再按源回退；无私有认证 |
| F6 | UI/原型 | 范围 | 本 PR runner-only；引用的 `plans/ui-prototype-v2/harness-evolution.html` 在当前 main 不存在，无 UI 改动 |

## §2 设计核对

- 数据流：dataset import 校验源 → manifest `image_sources` → tasks payload → `buildCaseTask` → `imageCandidates` → `docker pull`。
- 兼容：旧 manifest 无 `image_sources` → 不解析，原行为。
- 固定池：本地镜像 `image inspect` 命中直接用，不增加 pull。
