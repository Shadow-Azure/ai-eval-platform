## §1 一页速览

**一句话**：把「模型凭据」从一张写着“后续里程碑接入”的门牌，变成可以真正开柜、换锁、销钥匙的前台。

**比喻**：页面是仓库前台的目录卡，数据库里的 `credential` 是保险柜。前台只能看到钥匙编号的后四位（掩码），不能把钥匙拿出来；换钥匙时前台收走新钥匙、放进保险柜并只更新编号；销钥匙只是把编号标成失效，不搬走历史账本。Runner 拿到的也不是这把长期钥匙，而是平台按次换发的临时门禁卡。

**交付块**：

| 交付块 | 落点 | 用户可见结果 |
|---|---|---|
| 列表与详情 | `ModelsPage.tsx`、`GET /model-configs` | 服务商、端点、模型、协议、价格、掩码、最近使用、累计用量 |
| 新建/编辑 | `ModelConfigDrawer`、`POST/PATCH /model-configs` | 新建 Key 或绑定已有凭据；编辑价格/协议/端点 |
| 连通性 | `POST /model-configs/:id/test` | 成功/失败卡片状态；失败弹窗带错误码与字段 |
| 轮换/撤销 | `POST /credentials/:id/rotate`、`DELETE /credentials/:id` | 掩码更新、旧 Key 失效、撤销后预检阻塞 |
| 权限 | `require_admin` + 页面角色 | 成员只读；写操作 API 403 |
| 向导串联 | `EvalWizardPage.tsx` | 新配置即时可见；撤销凭据有标记与阻塞提示 |

**验证基线**：全量 pytest 通过（1 skip）；`npm run build` 通过；`verify:docs`/`verify:flow`/`verify-flow --diff origin/main` 通过；浏览器冒烟 34/34 + 失败诊断 3/3；16 场景、37 断言、0 缺陷。

## §2 架构导览

### 2.1 控制面：把“目录卡”和“保险柜”拼在一起

`backend/app/api/model_configs.py:110` 的 `_config_payload` 是这次的关键粘合层：它在既有 `model_config_payload` 之上追加三样东西——`credential`（来自 `credential_payload`，只含 `secret_mask`/撤销时间等）、`last_used_at`、`usage`。这层不碰密文，密文只留在 `model_gateway/service.py` 的 `read_secret` 里。

列表端点 `model_configs.py:402` 先按租户/项目取配置，再一次性取凭据 map 和用 `_usage_by_config`（`:70`）聚合的用量 map，避免 N+1 查询；默认过滤 `is_temporary=False`，对应设计 05 §5“临时配置不进入公共目录”，诊断时可用 `include_temporary=true` 显式打开。

字段级错误是这次对错误 envelope 的最小扩展：`_error`（`:39`）接受 `fields`，统一挂到 `detail.error.fields`；`_connectivity_fields`（`:157`）把网关错误码翻译成 `secret` 或 `base_url`，因此页面能就地把红字落在正确的输入框，而不是只弹一个 Toast。

### 2.2 前端数据层：先归一化，再让组件保持“哑”

`web/src/api/models.ts` 负责所有 DTO 解析：`parseModelConfig`（`:114`）把未知 JSON 收窄成 `ModelConfig`，凭据解析只取 `secret_mask`；`fetchModelConfigs`（`:145`）和 `fetchCredentials` 分别读取目录与绑定候选。`createModelConfig`/`updateModelConfig`/`testModelConfig`/`rotateCredential`/`revokeCredential` 都是薄函数，页面不直接拼 fetch。

`web/src/api/evaluations.ts:193` 的 `errorFields` 同时识别 `error.fields` 与 `error.details.fields`（既有评测接口把字段放在 details 下），`ApiError`（`web/src/api/types.ts:31`）因此多了一个 `fields` 只读属性；这是向后兼容的增量，其他调用方不受影响。

### 2.3 页面：一个列表 + 四类覆盖层

`ModelsPage`（`web/src/pages/ModelsPage.tsx:471`）只做编排：查询、搜索、可用计数、测试状态和四类覆盖层（新建/编辑抽屉、详情抽屉、替换 Key、撤销、失败诊断）。

- `ModelConfigDrawer`（`:204`）承载新建/编辑；`Form.useWatch` 只用来切换“新建凭据 / 已有凭据”。
- 卡片（`:720` 起）负责把 `display_name/provider/model_name/api_style/pricing/secret_mask/last_used_at` 转成一个可扫读的目录卡。
- `menuFor`（`:667`）把详情、编辑、测试、撤销收进“更多”菜单；成员只剩详情。
- `footerStatus`（`:695`）优先显示本次会话的测试结果，其次撤销，最后是最近使用——状态不只靠颜色，旁边都有文字。
- 失败诊断 Modal（`:1039`）把 `error.fields` 摊开成“字段 + 原因”，并给出修复建议。

### 2.4 权限与秘密边界

页面角色只决定“看不看得见按钮”，真正边界在 API：`POST /model-configs`、`PATCH`、`/test`、`POST /credentials`、`rotate`、`DELETE` 都挂 `require_admin`。只读成员仍能 `GET` 列表/详情与 `/credentials?kind=model`，但看不到密文。

秘密卫生靠三条工程约束而不是口头承诺：Key 只出现在 `Input.Password` 与一次 `fetch` body 中；新建/轮换不经过 React Query 的 mutation 缓存（直接调 API 函数）；页面从不把 Key 写进 URL、localStorage/sessionStorage 或查询 key。

## §3 数据流走查

**主线剧本：管理员配置一个模型并让向导立刻可用。**

1. 登录后打开 `/models`，`useQuery(["model-configs"])` 经同源 `/api` 打到 `GET /api/v1/model-configs`（`ModelsPage.tsx:471`）。
2. 控制面 `list_model_configs`（`model_configs.py:402`）过滤临时配置，取配置、凭据 map 与 usage map，逐个 `_config_payload`（`:110`）返回；页面把 `credential.secret_mask` 渲染成 `****8c21`，把 `usage.requests` 渲染进详情。
3. 点“添加模型凭据”打开 `ModelConfigDrawer`（`:204`）；默认“本次新建凭据”，输入服务商/端点/模型/协议/价格/Key。
4. 提交时 `createModelConfig`（`models.ts:160`）只发一次 `POST /model-configs`，body 里带 `secret`；服务端 `create_model_config` 校验 base_url/API style，加密 Key，写 `credential` 与 `model_config`。响应只回 `credential.secret_mask`。
5. 页面关闭抽屉、失效 `["model-configs"]` 与 `["model-credentials","model"]`；默认再调 `/test`（`test_model_config`，`model_configs.py:493`），成功则在卡片显示“刚刚验证通过”，失败则打开诊断 Modal。
6. 刷新页面：浏览器没有可回放的 Key 状态，`GET` 重新返回掩码；URL 仍是 `/models`。
7. 打开“发起评测”，`fetchModelConfigs` 再次拿到刚建的配置；选到已撤销凭据时，标签与 Alert 提醒预检会阻塞。
8. 运行一致性检查：`POST /evaluations/prepare` 返回 `credential_unavailable` 阻塞项，页面禁用“创建评测”。

**轮换分支**：卡片“替换 Key” → `POST /credentials/:id/rotate` → 服务端重加密、清 `revoked_at`、更新 `secret_mask` → 页面失效查询并复测；旧 Key 在服务端即刻不可解密。

**撤销分支**：菜单“撤销凭据” → `DELETE /credentials/:id` → 服务端只写 `revoked_at`，不删历史 → 卡片显示“已撤销”，`available` 计数下降，预检继续阻塞。

## §6 讨论点

### D1 · 轮换/撤销没有“再次认证”

- **位置**：`web/src/pages/ModelsPage.tsx:969`（替换 Key 弹窗）、`:1016`（撤销确认）；后端 `POST /credentials/:id/rotate`、`DELETE /credentials/:id`。
- **现象**：设计要求“替换 Key 需要再次认证”，实现复用管理员会话 + 二次确认弹窗，没有再次输入密码或短期 re-auth token。
- **问题**：共享浏览器会话被借用时，管理员可以在不知道密码的情况下换掉 Key；影响面是“拿到已登录会话的人”。
- **预判**：当前平台是单租户、管理员数量少，二次确认 + 审计（后续）能覆盖主要误操作；真正的会话劫持风险应由更短的会话 TTL / step-up auth 解决，而不是在单个表单里加密码框。
- **结论**：（留空，供拍板）

### D2 · “最近验证状态”不持久化

- **位置**：`ModelsPage.tsx:532` 的 `performTest`、`:695` 的 `footerStatus`。
- **现象**：刷新后测试结果回到“最近使用/尚未使用”，只有本次会话内的结果保留。
- **问题**：管理员无法在离开页面后回看“上次验证成功是什么时候”；原型里“8 分钟前验证”的语义没有持久化。
- **预判**：issue 的验收只要求“最近使用情况”；持久化验证状态需要新增列与迁移，收益有限，先留作后续。
- **结论**：（留空，供拍板）

### D3 · 列表没有分页

- **位置**：`backend/app/api/model_configs.py:402`、`ModelsPage.tsx:471`。
- **现象**：`GET /model-configs` 一次返回全部配置，页面全量渲染。
- **问题**：模型配置通常是个位数，但若接入几十个供应商/临时配置，首屏和搜索会变重。
- **预判**：M5 阶段规模小，不值得为分页增加 API 与 URL 状态；等真实使用超过 ~50 条再引入。
- **结论**：（留空，供拍板）

### D4 · 并发编辑是 last-write-wins

- **位置**：`backend/app/api/model_configs.py` 的 `patch_model_config`、`ModelConfigDrawer` 的初始值。
- **现象**：两个管理员同时打开编辑，后保存的覆盖先保存的；没有 `updated_at`/版本号冲突提示。
- **问题**：价格、端点被静默覆盖，可能影响后续评测成本。
- **预判**：单租户管理员协作频率低；要根治需要乐观锁字段与 409 冲突页，属于跨模块契约变更。
- **结论**：（留空，供拍板）

### D5 · AntD 静态 message 与重复 DOM id

- **位置**：`ModelsPage.tsx` 里的 `message.success/error`、抽屉与弹窗中重复的 `#secret`。
- **现象**：控制台出现 AntD “Static function can not consume context” 警告；页面上同时存在隐藏抽屉和可见弹窗的 `#secret`。
- **问题**：警告是仓库既有模式（`EvalsPage` 等同样使用静态 message），不是本 PR 新增的独有缺陷；重复 id 在自动化里需要更精确的可见性选择器。
- **预判**：不阻塞功能；若要清理，应把全站 message 切到 `App.useApp()`，属于独立的小重构。
- **结论**：（留空，供拍板）

## §9 文件级代码分析

### 9.1 `backend/app/api/model_configs.py`（M）

**职责**：模型配置/凭据的控制面 API；本次把“列表可读性”和“错误可定位”补齐。

**关键依赖**：沿用 FastAPI + SQLAlchemy + 既有 `model_gateway.service` 的序列化；没有引入新依赖。

**变更块**：

- 旧 `_error` 只有 code/message；新 `_error` 增加可选 `fields`，形状与 M4-03 资源接口一致。这样前端不必按错误码硬编码字段名。
- 新增 `_usage_by_config`：一条 `GROUP BY model_config_id` 聚合，取 `max(created_at)` 与 token/cost 求和；SQLite 返回的 naive datetime 由 `_as_datetime` 补 UTC，避免“最近使用”偏 8 小时。
- 新增 `_config_payload`：在纯函数 `model_config_payload` 外套一层控制面视图，只加掩码凭据和用量；密文/`key_version` 不进入返回。
- `list_credentials` 增加 `kind` 过滤；`list_model_configs` 增加 `include_temporary`，默认隐藏临时配置。
- `test_model_config` 的错误统一经 `_connectivity_fields` 映射到 `secret`/`base_url`。

**实现思路**：读接口做“一次查询 + 内存拼接”，写接口继续复用原有加密/校验；错误只加结构化字段，不改状态码。

**检视发现**：无 P0/P1；`include_temporary` 是诊断开关，默认行为符合设计。

### 9.2 `tests/backend/test_model_credential_console.py`（A）

**职责**：锁住页面依赖的 API 契约。10 个测试分别覆盖列表掩码/用量、已有凭据绑定、kind 过滤、轮换/撤销、成员读写、连通失败字段、PATCH 校验、缺凭据、密钥不泄露、临时配置隐藏。

**关键依赖**：复用 `conftest` 的 SQLite + 迁移 + 管理员登录，局部假 provider 注入 `get_provider_client`。

**检视发现**：测试用真实 API 形状而不是 mock 序列化，能挡住“页面能看到但接口不返回”的回归。

### 9.3 `tests/backend/test_model_gateway.py`（M）

**变更**：原断言 `"secret" not in json.dumps(config)` 会被新增的 `credential.secret_mask` 误伤；改为断言顶层无 `secret`、无明文 Key、无 `ciphertext`，并显式检查掩码值。测试意图不变，精度提高。

### 9.4 `web/src/api/models.ts`（M）

**职责**：模型/凭据 DTO 与请求封装。

**变更块**：新增 `CredentialSummary`、`ModelUsageSummary`、`ModelConfig` 扩展字段、解析函数与 5 个写操作。解析函数对未知 JSON 做防御，不让页面拿到 `undefined` 价格/用量。

**关键约束**：`rotateCredential` 的 secret 只在函数参数与 fetch body 中存在，不进入任何 query key；这使“查询缓存不含秘密”成为结构性事实。

### 9.5 `web/src/api/evaluations.ts` + `types.ts`（M）

**变更块**：`errorFields` 兼容 `error.fields` 与 `error.details.fields`；`ApiError` 增加 `fields`。

**为什么**：既有评测接口把字段放在 details 下，新模型接口放在 error 下；统一解析后页面只依赖 `ApiError.fields`。

### 9.6 `web/src/pages/ModelsPage.tsx`（A）

**职责**：页面编排 + 表单 + 覆盖层。

**关键依赖**：AntD `Form/Drawer/Modal/Dropdown` 与 TanStack Query；没有新增第三方包。

**变更块分析**：

1. **查询与派生**（`:471` 起）：`useQuery` 取列表与凭据候选；`configs` 再过滤临时配置（与后端双保险）；`available` 只数“有凭据且未撤销”的项。

3. **新建/编辑**（`:204`）：Key 输入是 `Input.Password`；`credential_mode` 控制“新建/已有”分支；提交成功后 `form.resetFields()` 清掉内存中的 Key。
