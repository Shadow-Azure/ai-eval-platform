## §1 一页速览

一句话：把「测试环境里长出来的一行 antd 默认样式」按原型重新排版，让名称、最近启动和操作区各归其位，并在窄屏主动收起次要列。

比喻：原来的快速启动行像一张被塞进太多字的名片，名字用蓝色超链接写、最近启动竖着挤在角落、还多贴了一张「启用」贴纸；现在换成原型的名片模板——名字用深色粗体写在左上，状态和日期并排放在右侧，按钮只留「详情 / 启动」，窄屏时把日期一行收进口袋。

| 交付块 | 结论 |
|---|---|
| 名称 | 12px / 650 / 蓝色链接 → 13px / 700 / `#1f2937` 文本按钮，可换行 |
| 最近启动 | 纵向纯文本（宽 48px）→ 标签 + 时间同行（宽 70.9px） |
| 操作区 | 启用 + 详情 + 启动（163.2px）→ 详情 + 启动（117.2px） |
| 行高 1500 | 65.2px → 60.6px，与原型 60.6px 一致 |
| ≤1240px | 最近启动仍显示 → `display: none`，名称不覆盖相邻列 |
| 视觉对比 | 1500 / 1200 两档修改前后 + 原型截图，见 PR 描述与证据 release |
| CI | flow-offline、flow-online、docs、web、runner、deployment 全部通过（代码 head `b45ecb6`，文档提交只改本文件） |

验证基线：本机 Vite + 临时 mock 控制面，Chrome headless，1500×837 与 1200×837、`deviceScaleFactor=2`、浅色主题；修改前取自 `main@55bb176`，当前基线 `main@6935ef8` 的页面代码相同；截图见 release `m10-388-quick-start-evidence-20261123`，mock、脚本和截图均未提交进代码仓。

集成冒烟 8/8 通过（3 个模板渲染、状态标签、停用按钮、详情导航、启动弹层、1200px 隐藏最近启动、无横向滚动），冒烟截图与原型同视口、同数据对比见 PR 描述与 release 内 `smoke-report.html`。

## §2 架构导览

### 2.1 数据来源没有变化

`web/src/pages/EvalsPage.tsx:96-100` 仍用 `fetchEvalTemplates({ limit: 3 })` 取最近模板；本次只改渲染。固定组合文本抽到已有的 `templateComboText()`（`web/src/components/TemplateBits.tsx:39-47`），避免页面里再维护一份拼接逻辑。

### 2.2 行布局：flex + 可收缩主列

`web/src/styles/templates.css:7-23` 把列表改成 `flex column`，行改成 `display: flex`、`gap: 12px`、`padding: 11px 0`、`border-bottom: 1px dashed`，列表 `padding: 0 19px 14px`。与原型 `prototype/styles.css:4686-4702` 一一对应。

`templates.css:36-39` 的主列 `flex: 1; min-width: 0` 是关键：它允许名称在列内换行，而不是把相邻列顶开；`templates.css:70-78` 的最近启动和 `87-92` 的操作区都是 `flex: 0 0 auto`，不参与压缩。

`templates.css:99-103` 的 `@media (max-width: 1240px)` 隐藏 `.quick-template-last`，对应原型 `prototype/styles.css:4756-4758`。这样窄屏优先保留名称和操作，不保留最近启动。

### 2.3 名称：普通文本按钮，不是 antd Link

`web/src/pages/EvalsPage.tsx:308-315` 用原生 `<button type="button">`，`title` 保留完整名称。`templates.css:41-59` 给它 13px / 700 / `var(--ink)`、透明背景、无边框、左对齐、`white-space: normal` 与 `overflow-wrap: anywhere`，hover 变主色。

这解决了两个问题：视觉上不再是蓝色链接；布局上名称可以在主列内换行，`overflow-wrap: anywhere` 兜住没有空格的长名称，避免再次画到下一列。

### 2.4 最近启动：状态标签 + 时间

`TemplateBits.tsx:93-102` 新增 `TemplateLastRunTag`：有最近运行时按 `evalStatusMeta(run.status).label/color` 输出 antd `Tag`；没有最近运行时输出中性「尚未启动」；有 `last_launched_at` 但没有运行记录的历史模板输出「已启动」，保留旧语义。

`EvalsPage.tsx:318-321` 把标签和 `dateTimeLabel(last_launched_at)` 放在同一行，`templates.css:70-85` 控制 `gap: 6px` 与 10px 字号。

### 2.5 操作区与事件

`EvalsPage.tsx:322-336` 移除了 `TemplateStatusTag`，只留「详情 / 启动」。两个按钮仍走原来的 `navigate` / `setLaunchTarget`，没有改启动弹层逻辑。停用模板的启动按钮补了 `title="模板已停用"`，对应原型 `prototype/app.js:1298-1300`。

## §3 数据流走查

1. 进入 `/evals`，`templatesQuery` 请求 `GET /api/v1/eval-templates?limit=3`。
2. 返回的模板按 `quick-template-row` 渲染：图标 → 名称 + 组合 → 最近启动标签 + 时间 → 详情 / 启动。
3. 1500px 下名称单行 20.1px 高，组合行 15.5px，行高 60.6px；最近启动宽 70.9px，操作区 117.2px。
4. 1200px 下媒体查询命中，最近启动 `display: none`；主列宽度 704.8px，名称 692.4px，单行放下，无相邻列重叠。
5. 点击名称或「详情」跳到 `/evals/templates/<id>`；点击「启动」打开 `TemplateLaunchModal`，弹层读取同一个 `EvalTemplate`，不依赖行布局。
6. 原型用同一份模板数据、同一视口渲染，名称、标签、按钮结构一致。

## §6 讨论点

### D1 快速启动行不再展示解决率

- **位置**：`web/src/components/TemplateBits.tsx:93-102`、`web/src/pages/EvalsPage.tsx:318-321`
- **现象**：修改前 `templateLastRunLabel()` 对最近运行输出「已完成 · 87%」；修改后标签只输出「已完成」，解决率仍可在模板列表和详情页看到。
- **问题**：快速启动行是否需要在状态标签里保留解决率？
- **预判**：原型 `templateLastRunTag()` 只输出状态标签，issue #388 也要求「标签 + 时间同行」；快速启动区只承担入口作用，解决率放在完整列表/详情更合适。保持现状。
- **结论**：（留空给用户拍板）

### D2 1200px 名称单行放下而不是换行

- **位置**：`web/src/styles/templates.css:41-55`、`web/src/styles/templates.css:99-103`
- **现象**：同一条长名称在原型 1200px 下换成两行（行高 80.8px），生产修改后主列 704.8px、名称 692.4px，单行放下（行高 60.6px）。
- **问题**：这是否算与原型不一致，需要强制换行？
- **预判**：原型换行是因为它在该视口的主列恰好比文本窄约 0.4px；生产页面壳给主列多约 12px。设计意图是「名称不能覆盖下一列」，不是「必须两行」。当前已满足无重叠，强制换行只会多出空白。保持现状。
- **结论**：（留空给用户拍板）

### D3 没有自动化视觉回归

- **位置**：`web/src/styles/templates.css:7-103`
- **现象**：本次用临时 Playwright 脚本做 1500 / 1200 截图和 DOM 断言，仓库没有 Playwright 或视觉基线基建；issue #388 建议「截图或 DOM 断言」。
- **问题**：下一次改这一行仍可能再次漂移。
- **预判**：引入浏览器测试依赖、CI 浏览器和截图基线是独立基础设施改动，超出本 issue 的局部 UI 修复；先把测量结果写进 PR 和本检视文档，后续可用同一场景补 Playwright。不阻塞本 PR。
- **结论**：（留空给用户拍板）

### D4 「尚未启动」文案同时影响完整列表和详情

- **位置**：`web/src/components/TemplateBits.tsx:76-90`
- **现象**：`recentRunLabel()` 与 `templateLastRunLabel()` 的无运行文案从「从未启动」改为「尚未启动」，完整列表与详情页也会跟着变。
- **问题**：这是有意统一，还是应该只改快速启动？
- **预判**：原型两个位置都用「尚未启动」；统一文案减少同一状态两种说法。属于展示文案，无行为影响。
- **结论**：（留空给用户拍板）

## §9 文件级代码分析

### 9.1 `web/src/components/TemplateBits.tsx`

**职责**：模板展示的共享格式化与标签组件；本次新增最近启动标签，并统一无运行文案。

变更前（旧）：
```tsx
export function recentRunLabel(template: EvalTemplate): string {
  const run = template.recent_runs?.[0];
  if (!run) return "从未启动";
  ...
}

export function templateLastRunLabel(template: EvalTemplate): string {
  return template.recent_runs?.[0] || template.last_launched_at
    ? template.recent_runs?.[0] ? recentRunLabel(template) : "已启动"
    : "从未启动";
}
```

变更后（新）：
```tsx
if (!run) return "尚未启动";
...
    : "尚未启动";

export function TemplateLastRunTag({ template }: { template: EvalTemplate }) {
  const run = template.recent_runs?.[0];
  if (!run) return <Tag>{template.last_launched_at ? "已启动" : "尚未启动"}</Tag>;
  const meta = evalStatusMeta(run.status);
  return <Tag color={meta.color}>{meta.label}</Tag>;
}
```

实现思路：标签只负责状态语义，解决率等细节仍由 `recentRunLabel()` 提供；没有运行记录时用中性标签，保留「有启动时间但没有运行记录」的旧模板兼容分支。
