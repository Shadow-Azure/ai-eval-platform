## §1 一页速览

一句话：**模板过去只能固化“怎么跑”，现在也能固化“跑完把坏件寄到哪里”，而且仓库钥匙只存在平台的保险柜里。**

比喻：一张已经盖章的派工单（模板）原来只写数据集、Agent、模型、资源池；现在多了一栏“坏件回收地址 + 工作区 + 钥匙”。派工单在保存时把地址和加密后的钥匙一起收进档案；每次一键启动时，平台从档案里取出钥匙，交给既有的 prepare/create 流程；若钥匙丢了或档案不完整，启动在创建任务前就拒绝，不会留下“看起来启动成功但永远不会上报”的评测。

| 交付块 | 内容 |
|---|---|
| 持久化 | `eval_template` 四列：enabled / base_url / workspace_id / token_encrypted |
| 写入 | 创建/更新接受 `self_evolution`；令牌 Fernet 加密；更新省略令牌保留密文；停用清空 |
| 读取 | 视图只返回 `{enabled, base_url, workspace_id, has_token}`，令牌从不回显 |
| 启动 | 解密令牌 → `build_preparation`；配置损坏在创建 run 前 422 |
| 前端 | 向导保存、详情、启动确认、列表标签均展示上报目标 |
| 验证 | 后端 1069 passed / 1 skipped；web typecheck/build；本地真实应用冒烟 9/9 |

验证基线：后端 CI `backend (pytest + migration)` pass（7m37s）；docs、flow-offline、web、runner、deployment contract 全 pass；flow-online 仅缺 Project 关联（需人工在 PR 侧栏添加）。

## §2 架构导览

### 2.1 数据与写入：四列 + 一个受控的写模型

`backend/migrations/versions/0033_eval_template_self_evolution.py` 增加四列；`models/evaluation.py:462-470` 映射到 ORM。API 层 `api/eval_templates.py:23-45` 定义请求模型，`create/update` 复用同一个 `TemplateSelfEvolutionRequest`；真正的字段规则放在服务层，保证直接调用服务也不能绕过（`services/eval_templates.py:291-331`）。

服务层的关键取舍：**写模型不把令牌放进视图**。`_self_evolution_columns` 只返回四个数据库列；`template_view`（`services/eval_templates.py:700-711`）返回 `has_token` 布尔值。这样“模板详情”和“模板快照”都可以安全地进入浏览器或 `eval_run.template_snapshot_json`。

### 2.2 更新语义：省略 = 保留，停用 = 清空

`services/eval_templates.py:485-498` 只在 `changes["self_evolution"]` 存在时更新四个列；未提供或显式 `null` 时保留原值。`_self_evolution_columns` 在 enabled=true 且没有新令牌时，优先复用 `existing_ciphertext`；只有“从零启用且无令牌”才抛 422（`services/eval_templates.py:315-324`）。停用走 `normalise_self_evolution` 的空值分支，四个列全部清空。

### 2.3 启动：先解密，再准备，失败不落半条 run

`services/eval_templates.py:847-881` 的 `_self_evolution_launch_payload` 在解析资产、校验镜像与容量之前执行：enabled 但缺地址/工作区/密文、或密文无法解密，直接 `TemplateInvalid(field="self_evolution")`。成功时把明文令牌与地址/工作区传入 `build_preparation`（`:938-945`），由既有 prepare/create 链路加密落到 `eval_run`。因此 run 的四个 self_evolution 列与模板配置一致，终态仍由 M9 worker 的 outbox 上报。

### 2.4 前端：一个 payload + 三处展示

`EvalWizardPage.tsx:1064-1115` 的 `buildTemplatePayload` 是唯一保存入口；enabled 时要求当前会话里仍有令牌（草稿从不持久化令牌），disabled 时只发 `{enabled:false}` 让后端清空。`TemplateBits.tsx:12-34` 提供列表标签与详情/启动共用的文案；`TemplateLaunchModal.tsx:87` 的标签列宽 120px 修复了冒烟发现的换行。详情页 `EvalTemplateDetailPage.tsx:240-248` 与启动确认 `TemplateLaunchModal.tsx:118-125` 都只显示目标与“令牌已配置/未配置”。

## §3 数据流走查

场景：用户在向导 Step 3 启用上报，保存为模板，再从模板一键启动。

1. 向导 Step 3 填写 `https://harness-evolution.example.com`、`ws-smoke-01`、`whk_…`；`buildTemplatePayload` 把这些字段放进 create 请求（`EvalWizardPage.tsx:1104-1112`）。
2. API 的 `TemplateCreateRequest` 接收 `self_evolution`（`api/eval_templates.py:59`）；服务 `normalise_self_evolution` 校验，`encrypt_self_evolution_token` 生成 Fernet 密文，模板行写入四列（`services/eval_templates.py:404-413`）。
3. 模板详情/列表读取 `template_view`，只拿到 `has_token=true`（`services/eval_templates.py:700-711`）；前端渲染“已启用 · host · 工作区 ws”和“令牌已配置”，不出现明文。
4. 一键启动：`launch_template` 先 `_self_evolution_launch_payload` 解密令牌（`services/eval_templates.py:847-881`），再调 `build_preparation(..., self_evolution={enabled:true, base_url, workspace_id, token})`（`:938-945`）。
5. `build_preparation` 再次校验并加密，把非密字段写入快照、密文写入 preparation；`consume_preparation` 复制到 `eval_run` 四列。终态 worker 用同一令牌 POST HE。
6. 若模板行被手工清空/密文损坏，第 4 步在创建 run 前返回 422；不会产生永远不上报的 run。

### 6.2 没有模板编辑 UI

### 6.3 更新时显式 `null` 的语义

- 位置：`backend/app/services/eval_templates.py:485-498`
- 现象：PATCH `self_evolution: null` 与“省略”一样保留原配置；只有 `{enabled:false}` 才清空。
