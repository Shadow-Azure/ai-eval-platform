## §1 一页速览

一句话：把“扫描到了资产”和“资产真的能跑”分开——扫描时记录依赖 CLI 的前置，源状态因此可能停在 `requires_setup`；同时把只读成员的“不能做什么”从一句页级说明落到每张连接卡片，并让取消评测的确认框说清费用和不可逆范围。

一个比喻：前置依赖像电器的插头规格。以前只要把电器放进仓库就算“可用”；现在扫描会读出说明书上的“需要 openspec 插座”，于是状态灯亮黄，并在卡片上贴一张“缺插座”的提示，而不是等通电时才炸。

交付块：

## §2 架构导览

### 2.1 扫描层：把说明书读出来

`_frontmatter` 之前只取 `name`/`description`，现在同时取 `compatibility`（`backend/app/services/agent_assets.py:138`）。OpenSpec 的真实 SKILL.md 写的是 `compatibility: Requires openspec CLI.`，`_runtime_prerequisites` 用正则 `requires ... cli` 抽出 `openspec CLI`（`:164`），并用 `path+content` 关键词兜底，覆盖没有该字段但正文提到 `openspec` 的生成型命令（`:376`、`:389`）。技能资产此前固定 `prerequisites: []`，现在也走同一函数（`:373`）。

### 2.2 状态层：有前置就不算 ready

`_scan_status`（`:184`）取代三处 `"ready" if assets else "requires_setup"`（`:613`、`:956`、`:1070`）：无资产仍为 `requires_setup`；有资产但任一资产带前置也标 `requires_setup`；否则 `ready`。这个状态只被读取与展示，未参与派发或预检阻塞（全仓 grep `requires_setup` 仅模型、迁移、服务赋值与前端标签）。

### 2.3 展示层：前端不猜状态

`AssetsPage` 的 `runtimeRequirements`/`generatedCommands` 只读 `asset.metadata.prerequisites`（`web/src/pages/AssetsPage.tsx:71`、`:79`），由 `RuntimeRequirementNote` 统一渲染（`:85`），卡片传入 `source.last_scan.assets`（`:747`），详情抽屉传入快照或最近扫描的资产（`:605`）。资源页的锁定态由 `session.role` 驱动（`ResourcesPage.tsx:274`、`:855`），弹窗不调用任何“提交申请”接口，只给说明与复制（`:327`、`:718`）。取消框直接读服务端聚合的 `budget_spent_cny`（`EvalDetailPage.tsx:1066`），不在前端估算。

## §3 数据流走查

剧本：只读成员打开资源连接页。

1. 登录返回 `role=viewer`，`isAdmin=false`（`ResourcesPage.tsx:265`）。
2. 连接列表来自 `GET /api/v1/connections`，仍是租户内可读；卡片头部渲染“无权限”而不是连接状态标签（`:855`），并把真实状态放进 facts 行（`:871` 附近）。
3. 卡片底部只出现“申请管理员权限”（`:927`），点击把连接对象放进 `permissionConnection`，弹窗展示当前角色与所需权限（`:730`）。
4. 点“复制申请信息”只写剪贴板，无网络写操作（`:327`）；用户自行发给组织 Owner。

另一条：OpenSpec 源扫描。

1. `stat source` 触发 `scan_source` → `scan_repository` 读取 SKILL.md。
2. frontmatter `compatibility` → `openspec CLI`；命令正文含 `openspec` 同样命中。
3. `_scan_status` 看到任一资产带前置 → 源状态 `requires_setup`。
4. `last_scan_json` 保存资产与前置；前端卡片与详情据此渲染提示，不需要额外接口。

## §6 讨论点

### 6.1 关键词兜底会不会过度标注

- **位置**：`backend/app/services/agent_assets.py:164-180`。
- **现象**：除 `compatibility` 外，只要路径或正文出现 `openspec` 就记 `openspec CLI`。
- **问题**：一个仅“提到 OpenSpec”的普通 Skill 会被标为需要 CLI，进而把整个源置为 `requires_setup`。
- **预判**：OpenSpec 是目前唯一有明确生成型命令链路的运行时；误标只会多一条提示、不阻塞执行，先接受。后续可扩展为读取 frontmatter 的 `dependencies` 或源级声明。
- **结论**：待拍板。

### 6.2 空扫描与“有前置”共用一个状态是否合适

- **位置**：`backend/app/services/agent_assets.py:184-195`。
- **现象**：`requires_setup` 同时表示“没扫到资产”和“资产存在但缺前置”。
- **问题**：两种情况的下一步动作不同（重扫 vs 准备运行时），同色标签可能让人误判。
- **预判**：这是既有语义，改动会波及状态枚举与迁移；本 PR 保持兼容。卡片文案和资产数量已能区分两者（0 个 vs 12 个）。
- **结论**：待拍板。

### 6.3 生成型 Command 的数量为什么是 0

- **位置**：`web/src/pages/AssetsPage.tsx:79`。
- **现象**：OpenSpec 真实扫描显示 12 Skill、0 Command，提示只说“依赖该 CLI 的生成型 Command”，没有“6 个”。
- **问题**：原型 mock 把 `opsx/*` 生成命令列进源，真实仓库里它们由 `openspec init` 生成、不在 Git 树内。
- **预判**：这不是数据造假空间，方向应保持“扫描到什么标什么”；若要让数量可见，需要源级声明或运行时探测，属于后续增强。
- **结论**：待拍板。

### 6.4 权限申请不落库会不会算“前端假状态”

- **位置**：`web/src/pages/ResourcesPage.tsx:327`、`:718`。
- **现象**：弹窗只给说明和复制，没有“已提交”toast。
- **问题**：原型点击“提交申请”会提示已提交，本实现刻意不做假成功。
- **预判**：符合 issue“不做前端假状态”的约束；真正要落库需要申请实体、审批流与通知，超出 M5-20。
- **结论**：待拍板。

### 6.5 只读成员看到掩码是否越界

- **位置**：`web/src/pages/ResourcesPage.tsx:880` 附近。
- **现象**：viewer 仍能看到 `****cret` 掩码与连接元数据。
- **问题**：m5-03 要求“普通成员只能查看授权信息”，掩码是否属于授权信息。
- **预判**：与模型凭据页一致（只读成员可看掩码、不可轮换），未暴露明文；风险可接受。
- **结论**：待拍板。
