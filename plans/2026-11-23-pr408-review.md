## §2 架构导览

### 2.1 示例在组件内的生成位置

`TemplateApiModal` 只在 `template` 非空时渲染（`web/src/components/TemplateApiModal.tsx:20`）。新增的两段示例在组件函数体内生成：`listResponse`（`:22-39`）和 `launchResponse`（`:40-48`）。它们不是从后端读取的实时数据，而是按当前模板 `id/name` 插入后的静态契约样例，与原型 `templateApiBody` 的写法同源。

### 2.2 为什么用 `JSON.stringify` 而不是手写模板字符串

模板名称是用户输入，可能包含引号或反斜杠。直接拼字符串可能显示非法 JSON；`JSON.stringify` 负责转义，同时保持字段顺序与紧凑格式，和原型展示一致。React 把它作为文本节点放进 `<pre>`，不会再解释 HTML。

### 2.3 样式为什么用相邻兄弟选择器

`.template-api-code` 原先只有 `margin: 9px 0 0`（`web/src/styles/templates.css:319-332`）。启动接口现在有两个连续 `<pre>`，若都保留 9px 顶部间距，curl 与响应会显得粘连；新增 `.template-api-code + .template-api-code { margin-top: 8px; }`（`:334-336`）只覆盖第二个及之后的代码块，不影响首个代码块和状态/结果接口的单代码块。

## §3 数据流走查

1. 模板列表行或详情页点击「接口」→ `setApiTarget(row/template)` → `TemplateApiModal` 打开。
2. 组件用当前 `template.id` / `template.name` 生成列表与启动响应文本。
3. JSX 在列表项说明后渲染 `<pre>{listResponse}</pre>`（`:103`）；启动项在 curl 后渲染 `<pre>{launchResponse}</pre>`（`:117`）。
4. 相邻代码块的 CSS 规则把间距压到 8px。
5. 弹窗仍由既有 `max-height: calc(100vh - 48px)` 约束；正文 `.ant-modal-body` 内部滚动，footer 固定。

## §6 讨论点

### D1 示例中的 `enabled/version/launch_count/preflight` 是固定值 → 接受

- 位置：`web/src/components/TemplateApiModal.tsx:24-38`
- 现象：响应样例固定展示 `enabled:true`、`version:3`、`launch_count:18`、`preflight.ready`，只有 `id/name` 来自当前模板。
- 问题：若当前模板已停用或预检 blocked，示例值与真实模板状态不一致。
- 预判：这是 API 说明书的“响应长什么样”样例，不是模板实时状态；原型同样使用固定值，且 #406 只要求“示例使用当前模板 ID”。改成实时值会让示例随模板状态变化，反而偏离原型和“固定契约样例”的用途。
- 结论：保留固定样例，仅注入当前模板 ID/名称。✅ 接受。

### D2 启动示例用固定 `eval-007`，状态/结果示例用 `<run_id>` 占位 → 接受

- 位置：`web/src/components/TemplateApiModal.tsx:22,40-48`
- 现象：启动响应给出具体 `run_id`，状态/结果示例仍保留 `<run_id>`。
- 问题：读者可能疑惑为什么一个具体、一个占位。
- 预判：原型用 `eval-007` 与状态/结果的 `eval-004` 区分“启动返回”和“后续查询”；#406 明确要求状态/结果接口既有示例保持不变。统一占位或统一具体值都会改动既有示例。
- 结论：保留现状；示例的目的分别是“启动返回一个具体 run”和“用占位说明后续 URL 形状”。✅ 接受。

### D3 没有前端自动化组件测试 → 接受（有冒烟兜底）

- 位置：`web/src/components/TemplateApiModal.tsx`
- 现象：仓库当前只有一个 React + Ant Design 应用，没有 web 组件测试运行器；本次验证依赖 `tsc`/build 与 Playwright 冒烟。
- 问题：未来改文案/结构时缺少快速单测回归。
- 预判：引入 Vitest + Testing Library 是新依赖和门禁变更，超出 #406 的“补两段响应示例”范围。
- 结论：保留；用实际应用的 10 场景冒烟与 PR 截图留存证据。✅ 接受。

### D4 生产代码块 12px、原型 10px，换行点不同 → 接受

- 位置：`web/src/styles/templates.css:319-332`
- 现象：冒烟截图中启动响应在 `status_url` 附近换行，原型在 `tmpl` 后换行；弹窗高度 1027 vs 原型 958。
- 问题：严格并排看，行数与高度不完全一致。
- 预判：#406 明确“样式沿用 `.template-api-code`；不改弹窗既有布局”，生产既有代码块就是 12px。为对齐原型改字号会顺带改变状态/结果接口的既有展示。
- 结论：保留生产样式；PR 描述已说明这一环境差异。✅ 接受。
