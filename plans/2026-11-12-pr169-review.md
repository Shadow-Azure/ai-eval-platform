## §1 一页速览

一句话：把 #93 提供的 attempt 查询 API 做成可复制、可刷新、可回退的三栏诊断页，并让降级、未关联、时钟异常和权限差异都在界面上说清楚。

比喻：session tree 是目录柜，waterfall 是按时间或原生顺序排好的索引卡，inspector 是当前卡片的读卡器。原始文件像封存底稿，只有用户主动申请时才由档案管理员签发一张 5 分钟借阅条，而且借阅条不留在应用 URL 里。

| 交付块 | 结果 |
|---|---|
| 深链 | run/case/attempt/session/span/kind 全部进入 URL |
| 三栏布局 | session tree + waterfall + attributes/content/raw inspector |
| 数据质量 | degraded、unlinked、failed、root fragment、clock incomparable |
| 竞态隔离 | attempt/session/span 查询 key 隔离，AbortSignal，切换时清选择 |
| 大内容 | 点击后请求签名地址，不把全文复制进 DB 或应用状态 |
| 权限 | viewer 隐藏 thinking；raw/content 仅管理员可签发 |
| 安全 | 所有内容按 React 纯文本/`pre` 渲染，不执行 HTML/Markdown |

验证基线：9 个前端模型测试、Node 77、backend pytest 全量、docs-sync 8 门、flow、Web typecheck/build 与真实 GUI smoke。

## §2 架构导览

### 2.1 路由与入口

`web/src/app/routes.tsx:30` 注册 `/evals/:runId/cases/:caseRunId/trace`，并在 `web/src/app/nav.ts:52` 增加“会话轨迹”面包屑。`web/src/pages/EvalDetailPage.tsx:1215` 在用例表提供独立“轨迹”按钮，`:2827` 在用例抽屉提供当前 attempt 入口。

入口只传 row 的 `latest_attempt_no` 或抽屉当前选择，不在页面间共享组件状态；刷新后的恢复依据始终是 URL。

### 2.2 URL 作为选择权威

`web/src/features/traces/traceModel.ts:64` 解析 attempt/session/span，`:75` 解析并校验 span kind。`TracePage` 的 `updateSelection` 用函数式 `setSearchParams` 合并非当前字段；用户点击 attempt/session/span 时 push history，默认值补全时 replace history。

因此复制 URL、刷新、浏览器返回都能恢复同一选择，不会产生一组只存在 React state 的“隐藏选择”。

### 2.3 查询与竞态

`web/src/api/traces.ts:324` 到 `:396` 分别封装 attempt tree、span keyset 页、span detail、大内容 URL 与 raw URL。所有读取都接受 `AbortSignal`。

`TracePage.tsx:509` 的 attempt query、`:551` 的 span infinite query、`:591` 的 detail query 都把 case/attempt/session/span 放进 query key。切换到另一个 attempt 后旧 key 不再被当前视图消费；session 变化同样清空 span。

### 2.4 三栏联动

左侧 `SessionTree` 只从 API session parent 关系构造 linked/unlinked 两组（`traceModel.ts:80`）。中间 `Waterfall` 只从 API `parent_span_id` 推层级和深度，不根据时间或名称猜关系。右侧 inspector 使用独立 detail API，避免用分页列表里的摘要冒充完整详情。

### 2.5 质量与时间

attempt 文件状态先决定 failed/degraded/empty/pending，再看 case 聚合状态；`traceStatusForAttempt` 防止旧 attempt 误用最新的 case `ready`。

`buildSpanWindows` 在 `clock_comparable=false` 时完全退回 ordinal（`traceModel.ts:145`），不制造伪时间轴。缺失父 span 只在“全部”视图按当前 session 集合派生 root fragment，避免类型筛选掉父节点后误报。

### 2.6 权限与大内容

`TracePage.tsx:605` 与 `:614` 分别签发 raw/大内容地址。地址进入显式 Modal，由用户再次点击链接，规避异步 `window.open` 被浏览器拦截；地址只存在组件内存，不写 URL、localStorage 或 Query 持久层。

viewer 的 THINKING span 由 API 返回 `content_hidden`，前端在 `:346` 显示明确的权限说明，不渲染正文。

## §3 数据流走查

1. 用户从用例行/抽屉进入 trace URL；页面解析 attempt、session、span 与 `kind`。
2. attempt query 取 case 的 session 树、文件、质量、parser 与统计；缺少 attempt 时补最新 attempt。
3. flatten session 树，校验 URL session 是否属于当前 attempt；无效时选择第一个 root session 并 replace URL。
4. session span query 使用 `(ordinal,id)` 游标分页；Load more 只追加新页，并按 span id 去重。
5. 选中 span 后 detail query 读取完整属性与 `parent_missing`；切换 filter 清空 span，切换 session/attempt 清空下游选择。
6. 用户点击大内容/raw 后 POST 签名接口；成功时打开受控 Modal，用户显式点击短时链接。
7. 轨迹 pending/parsing 时 attempt 与 span query 每 3 秒刷新；终态/heartbeat 表达式停止轮询。

## §6 讨论点

### D1 span kind 未进入 URL

- 位置：`web/src/pages/TracePage.tsx:480`
- 现象：初版只把 attempt/session/span 写入 URL，filter 留在组件 state；浏览器返回或复制 URL 后丢失类型筛选。
- 问题：深链恢复不完整，且切换 attempt/session 会遗留旧 filter。
- 预判：把 `kind` 也作为 URL 可验证参数，并在 attempt/session 切换时清空。
- 结论：已修复，`readSpanFilter` 单测覆盖合法/非法值。

### D2 list API 不含 parent_missing

- 位置：`web/src/features/traces/traceModel.ts:129`
- 现象：#93 的列表 DTO 只含 `parent_span_id`，初版 waterfall 读取不存在的 `parent_missing`，根片段计数恒为 0。
- 问题：缺失父节点的 span 被显示成普通节点，用户无法识别数据质量。
- 预判：在“全部”视图按当前 session 的已加载 span 集派生 missing parent；选中详情再以 API 的 `parent_missing` 校正。
- 结论：已修复，新增 `markMissingParents` 回归。

### D3 旧 attempt 继承 case trace_status

- 位置：`web/src/features/traces/traceModel.ts:199`
- 现象：初版顶部直接显示 case 的 `trace_status`；选择无 trace_file 的失败 attempt 时仍显示“可用”。
- 问题：用户会把另一个 attempt 的轨迹状态误认为当前内容。
- 预判：failed/degraded 文件优先，空文件为 pending，只有最新 attempt 才使用 case 聚合。
- 结论：已修复并增加状态派生测试。

### D4 异步 window.open 被拦截

- 位置：`web/src/pages/TracePage.tsx:605`
- 现象：签名 API 成功后调用 `window.open`，Chrome 视为非用户触发的异步弹窗并拦截。
- 问题：地址签发成功但用户看不到文件，且没有可操作反馈。
- 预判：签名结果进入显式 Modal，由用户点击真实链接。
- 结论：已修复；真实 GUI 验证 raw 下载 HTTP 200，大内容在新标签打开 HTTP 200。

### D5 processing 文案未自动刷新

- 位置：`web/src/pages/TracePage.tsx:514`
- 现象：横幅承诺“导入完成后自动刷新”，初版查询没有轮询。
- 问题：页面只能手刷，承诺与行为不一致。
- 预判：pending/parsing 时 attempt 与 span query 每 3 秒刷新，终态停止。
- 结论：已修复。

### D6 深度计算 O(n²)

- 位置：`web/src/pages/TracePage.tsx:178`
- 现象：初版每个 span 都 `find` 父节点。
- 问题：Load more 后深度行数增长会反复扫描数组。
- 预判：构造父节点 Map 后单次解析。
- 结论：已修复；当前 100 条/页并可持续累加。

### D7 跨 session 深链可混用 inspector

- 位置：`web/src/pages/TracePage.tsx:590`
- 现象：手工构造 `session=A&span=B` 时，初版仍按 URL span ID 拉详情，右侧 inspector 可能展示另一个 session 的 span。
- 问题：深链没有校验 span 与当前 session 的归属，违反 attempt/session 选择一致性。
- 预判：详情返回必须与当前 session 匹配；匹配的同 session 深链 span 可补入 waterfall，跨 session 或 filter 不匹配则清除无效选择。
- 结论：已修复，新增 `spanBelongsToSession`、`mergeSelectedSpan` 及 URL 深链回归。

### D8 切换 span/filter 后签名地址残留

- 位置：`web/src/pages/TracePage.tsx:630`
- 现象：签发大内容地址后切换 span 或 filter，旧签名弹窗仍保留，容易误把旧内容当成当前 span。
- 问题：签名结果没有随当前诊断选择失效。
- 预判：任何会改变 span 可见上下文的操作都清理签名弹窗。
- 结论：已修复，切换 attempt/session/span/filter 均清理签名状态。

## §9 文件级代码分析

### `web/src/api/traces.ts`

职责：把 #93 的松散 JSON 响应收窄成类型安全的前端 DTO。它像海关：所有外部数据先经过字段、数组、数字和布尔值检查，再进入页面。

关键 API 都接受 `AbortSignal`。tree 响应解析 session children；span page 解析 `page_info.next_cursor`；download 接口只接受 `url + expires_at`，不把 object key 或凭据带入前端。

实现思路：薄封装、无全局状态、响应错误统一交给现有 `request`/`ApiError`。已知弱点：后端字段新增时需同步 parser，属于显式 DTO 的维护成本。

### `web/src/features/traces/traceModel.ts`

职责：放不依赖 React 的导航和数据形状逻辑，便于 Node 原生测试。

- `readTraceSelection`/`readSpanFilter`：URL 解析。
- `flattenSessionTree`：linked/unlinked 分组与默认 session。
- `mergeSpanPages`：按 id 覆盖去重。
- `markMissingParents`：root fragment。
- `buildSpanWindows`：时间轴或 ordinal 回退。
- `traceStatusForAttempt`：attempt 级状态，不误继承 case。

实现思路：输入宽、输出窄，页面不重复实现算法。已知边界：完整 session 树仍一次返回；超大树需要服务端 session 分页，当前设计未要求。

### `web/src/pages/TracePage.tsx`

职责：组合查询、URL、选择状态和三栏组件。

像调音台：attempt 是总输入，session 是分轨，span 是当前音轨上的时间点。切错总输入时，旧分轨必须立即静音；本页通过 query key 隔离和切换时清空选择完成这一点。

核心数据流：

```text
URL -> attempt query -> flat sessions -> selected session
    -> infinite spans -> selected span -> detail
    -> signed content/raw modal
```

实现思路：URL 是选择权威，React Query 是请求状态，组件 state 只保存非持久 UI（签名弹窗）。已知弱点：waterfall 只在容器内滚动，尚未做行级虚拟化；当前 100 条一页，后续大量 span 时可升级。

### `web/src/styles/trace-viewer.css`

职责：把原型 tracePage 的视觉语言复制到真实页面。

依赖是现有 `--primary`、`--line`、`--success-soft` 等令牌，不另造一套主题。主要断点：

- 默认 `270px / minmax(430px,1fr) / 360px`。
- 1360px 缩为 `240/390/320`。
- 1120px inspector 移到下一行。
- 900px 单列，tree 改为顶部 session selector。

已知边界：应用整体最小宽度仍是 1080px；本页在桌面窄宽度可用，不承诺手机完整 waterfall，符合设计 09 §7。

### `web/src/pages/EvalDetailPage.tsx`

职责：给出“从哪个用例、哪个 attempt 进入轨迹”的操作面。

用例表与抽屉各有一个入口。表内按钮 `stopPropagation`，不会同时触发行详情；抽屉使用当前选择 attempt，而不是永远跳最新 attempt。

### 路由、图标与文档

路由、nav、Icon 和 main.tsx 都是小基础件：注册路径、面包屑、文件图标和 CSS。`docs/architecture.md` 增加当前轨迹页事实，英文镜像同步并重录 i18n。

### `tests/trace-viewer-model.test.mjs`

职责：先用失败测试锁定 8 个行为，再实现绿色：

- URL attempt/session/span 与 kind。
- linked/unlinked flatten。
- 分页 id 去重。
- 时间轴/ordinal fallback。
- stale generation。
- missing parent root fragment。
- attempt 状态不继承。

测试不依赖 DOM，避免给项目引入新的测试运行时；真实组件交互由 Computer Use smoke 补证。

## §10 结论

三栏页面的路由、数据流、视觉结构、安全渲染和权限边界与 issue/设计/原型一致。检视中发现的深链、root fragment、attempt 状态、异步下载、轮询和深度计算问题均已修复。剩余项是大规模行虚拟化和 #95 的真实生产链路，不影响本 issue 合并。
