# 01 · 诉求分析与范围

## 1. 产品目标

平台的核心不是“把 Agent 跑一遍”，而是让一次评测具备四个可验证属性：

1. **可复现**：数据集版本、Runtime 版本、资产 commit、模型配置、资源环境和评分口径均被冻结。
2. **可观测**：用户能看到排队、执行、评分、轨迹处理和聚合进展，而不是只收到最终分数。
3. **可诊断**：任意用例都能关联到本次 attempt 的主/子 Agent 会话、工具调用、模型用量与原始文件。
4. **可扩展**：新增数据集、指标、Runtime、模型供应商和资源供给模式时，尽量新增适配器而不改主流程。

## 2. 十一条诉求的落地与验收

| 用户诉求 | 设计落点 | MVP 验收信号 |
|---|---|---|
| 1. 账号密码登录 | 登录页、签名会话、密码哈希、默认租户归属 | 错误密码有明确失败态；未登录深链跳登录；退出后会话不可再用 |
| 2. 配置添加数据集并可拓展 | 数据集/版本分离、适配器注册、导入三步向导、不可变任务视图 | SWE-bench Verified 可导入、校验、浏览；新增同 Schema 版本不改页面与 Runner |
| 2.1 查看用例数、指标和用例详情 | 数据集目录/详情、指标定义、服务端分页 | 用例总数与版本一致；指标说明可见；可查看题面、仓库、base commit 和测试定义 |
| 3. 配置模型并保存 API Key | 模型配置与凭据、掩码、KMS 信封加密、模型网关 | 支持 OpenAI 兼容端点；页面不回显明文；Runner 不接触长期 Key |
| 4. GitHub Actions 机制 + 阿里云竞价资源池 | 私有仓通用工作流、临时 Runner、连接与供给器、池标签 | 自有 Linux 与竞价 ECS 均能注册、接 Job、心跳和释放；连接能力不匹配会被拒绝 |
| 5. 启动时组合 Agent/Skill/模型/资源池 | 四步启动向导、Ref 解析、资产快照、已有或临时模型配置 | 提交前可检查完整配置；启动后所有分片使用同一不可变快照 |
| 6. 单租户起步，预留多租户 | 默认 tenant/workspace/project、归属列、仓储层作用域、资源配额字段 | 默认组织无切换复杂度；跨租户唯一约束和查询测试从首轮保留 |
| 7. 实时进展与可拓展结果 | 用例状态机、事件表、SSE、数据集驱动指标注册、测试级打点 | 刷新不丢进展；运行快照与最终结果明确区分；每个失败测试有状态、分组和完整日志 |
| 8. 会话元数据入库并跳转轨迹 | eval_case_run → trace_session → trace_span、版本化适配器、OSS 原件 | 用例行可定位对应 attempt；归一化失败仍可下载原始文件并看到处理错误 |
| 9. 查看主 Agent 和 subagent 轨迹 | 会话树 + waterfall + span 属性三栏 | 父子关系有原生证据；选择子 Agent 后瀑布与属性同步；无证据时标未关联 |
| 10. 并发与竞价资源分析 | 一 Runner 一 Job、分片、容量上限、配额、Spot 中断重试 | N 个在线 Runner 可并行 N 个用例 Job；无空闲资源时排队；实例回收不生成重复结果 |
| 11. 合入自动部署与更新数据库 | main 流水线、测试/构建/迁移/健康检查、expand-contract | 迁移失败阻断部署；健康检查失败回滚镜像；破坏性变更分版本发布 |

## 3. MVP 用户旅程

### 3.1 配置准备

```text
登录 → 导入数据集版本 → 查看校验和用例
     → 添加模型与凭据 → 连通性测试
     → 添加 Git 资产源 → 扫描并确认 Skill/Command/Subagent
     → 添加资源连接 → 创建资源池 → 测试供给与 Runner 心跳
```

准备阶段的每一步都可独立完成，但发起评测前必须再次检查资源可用性；列表里“上次可用”不能代替启动时校验。

### 3.2 发起与观测

```text
选择数据集版本
  → 选择 Runtime、资产源、Ref 与具体资产
  → 解析并冻结 commit / 资产摘要
  → 选择已有模型或临时模型、资源池、并发与重试参数
  → 创建评测 → 分片派发 → 实时进展
  → 用例执行/评分/轨迹处理 → 最终聚合
```

### 3.3 诊断

```text
评测详情 → 用例明细 → 状态筛选/搜索 → 选择用例
  → 选择 attempt → 会话树 → waterfall → span 属性/内容
  → 必要时下载脱敏后的原始轨迹与评分报告
```

轨迹处理是独立子状态。用例评分已完成而轨迹仍处理中时，结果页可以正常使用，轨迹页显示“处理中”，不能伪造空会话。

## 4. MVP 范围与非目标

### 4.1 MVP 包含

- 单组织、单工作区、单项目的账号密码登录与管理员/只读两类能力边界。
- SWE-bench 适配器、数据集版本导入、用例与指标浏览。
- OpenAI 兼容模型端点、已有凭据和仅本次评测使用的临时凭据。
- Git 资产源与 Superpowers/OpenSpec 类 Skill 资产的快照化交付。
- 私有 GitHub 仓库、自托管临时 Runner、Linux Docker 沙箱与阿里云竞价 ECS 供给。
- 用例并发、失败/超时/取消/重试、事件恢复和最终结果。
- Claude Code 轨迹端到端接入；Codex/OpenCode/pi 适配器接口、样本 fixture 和降级协议。
- 用例到主/子 Agent 轨迹的跳转、raw 文件下载和基础脱敏。
- main 合入后的阿里云部署与向前兼容迁移。

### 4.2 非目标

- 不做完整 IAM、组织管理、邀请、SSO、计费系统和跨租户资源共享市场。
- 不自研 SWE-bench 评分逻辑，不把模型评分与 Agent 执行混在一个进程。
- 不承诺所有 Runtime 首版都能无损恢复所有内部状态；无法归一化的部分保留原件并显式降级。
- 不在 MVP 替换 GitHub Actions 为自研队列，不在没有 K8s 的前提下引入 ARC。
- 不做通用工作流编排、多人协同编辑、结果公开分享和复杂 BI 报表。

## 5. 领域边界

| 领域 | 拥有的事实 | 不应该拥有 |
|---|---|---|
| Identity | 用户、会话、默认租户归属与角色 | 模型密钥、Runner 注册令牌 |
| Dataset | 数据集、不可变版本、用例、任务包清单 | 某次评测的结果 |
| Assets | Runtime、Git 资产源、扫描结果、不可变快照 | 执行中的可变 Git 分支状态 |
| Model | 模型配置、加密凭据、供应商连接信息 | 用例执行状态 |
| Resource | 连接、资源池、Runner、供给实例和容量 | 评分报告正文 |
| Evaluation | 评测、attempt、事件、结果快照 | Agent 原生文件的权威副本 |
| Trace | 归一化会话/span、导入状态、原件索引 | 评测调度规则 |
| Delivery | 部署记录、迁移版本与健康状态 | 业务评测状态 |

## 6. 可复现性的最小快照

创建评测时必须冻结：

```text
(dataset_version_id, dataset_adapter_version, task_bundle_digest,
 runtime_id, runtime_version, asset_snapshot_id, resolved_commit,
 model_config_snapshot, credential_reference_kind, resource_pool_snapshot,
 scoring_image_digest, metric_definition_versions, concurrency, retry_policy)
```

`credential_reference_kind` 只记录“已有/临时”及内部引用，不记录明文或将密文复制到评测快照。模型价格、显示名等可变信息以快照为准；供应商凭据轮换不应改变历史结果的可读性。
