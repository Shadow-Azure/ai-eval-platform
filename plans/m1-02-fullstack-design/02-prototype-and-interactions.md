# 02 · 原型与交互设计

## 1. UI 基线与信息架构

原型采用默认展开、可收起的左侧导航、顶部上下文区和内容工作区。视觉令牌来自 `prototype/styles.css`：主色 `#1677ff`、画布 `#f2f5fa`、卡片白色、10px 圆角、236px 展开侧栏、72px 收起侧栏、14px 基础字号；React 实现必须复用这些令牌，不让 Ant Design 默认主题覆盖原型语言。

侧栏底部提供「收起导航 / 展开导航」：展开态显示品牌与分组标题，收起态保留图标、当前页高亮和右侧 Tooltip；主内容与外边距同步过渡。偏好只写入浏览器 `localStorage` 的 `ep.sidebar.collapsed`，默认展开，不新增后端接口、表或迁移。

```text
工作台
  └─ 总览
评测
  ├─ 评测任务
  └─ 数据集
配置
  ├─ Agent 资产
  ├─ 模型凭据
  └─ 资源池
系统
  └─ 交付流水线
```

单租户阶段，组织切换器只显示默认组织；不展示空的工作区/项目选择器。顶栏保留通知、当前用户和环境健康入口，不让系统运维信息抢占评测主路径。

## 3. 关键页面交互

### 3.1 数据集目录与详情

- 目录卡片读取适配器元数据：名称、任务族、环境形态、最新版本、用例数、核心指标与接入状态；不硬编码 SWE-bench 字段。
- 详情页固定展示版本三元组“来源 + 上游提交/标签 + 适配器版本”、用例数量和预期指标。
- 用例列表服务端分页；用例抽屉展示标准字段与数据集特有 JSON，参考补丁/测试补丁默认折叠并标记敏感评测数据。
- 导入三步向导不允许校验失败后生成版本；部分用例失败时必须显示成功/失败数与可下载错误清单，不能仅显示 Toast。

### 3.2 Agent 资产

- 添加来源时先输入仓库、默认 Ref、扫描路径与选择方式，再自动扫描 Git tree。
- 文件树支持类型筛选、分页、逐项勾选、移出和手动补类型；移出只改变本次导入，不修改远端仓库。
- 发起评测时 Ref 默认继承资产源，但修改后必须重新解析；未解析、解析失败或选择为空均不能进入下一步。
- OpenSpec 等生成型 Command 显示运行时前置依赖；前置脚本属于快照的一部分并需审计，不允许任意资产源静默获得宿主机执行权限。

### 3.3 模型与凭据

- 列表仅显示掩码、供应商、端点、模型、最近验证状态；复制/查看明文不是产品能力。
- 替换 Key 需要再次认证；只读角色可以引用但看不到密文，也不能执行替换。
- 发起评测的“临时模型”默认不进入全局凭据列表；其生命周期覆盖本次评测全部重试，评测终态后按策略销毁。
- 连通性测试使用最小模型请求并返回脱敏错误；不能把供应商响应中的请求头或 Key 写入事件日志。

### 3.4 资源连接与资源池

- 先选择连接，再启用兼容供给模式；后端仍执行 `connection_provider_mismatch` 校验。
- 容量统一显示“在线 Runner 数 / 池上限”，另显示 busy/idle、排队 Job 和正在创建实例，避免把池上限误认为实时并发。
- 测试供给需要有明确费用提示、最长存活时间和自动释放；测试实例不承接真实评测。
- Runner 详情展示标签、最近心跳、当前 Job 的脱敏 ID 和临时注册状态，不展示注册 Token。

### 3.5 发起评测

四步为“数据集 → Agent/资产 → 模型/资源 → 确认”。建议将并发、单用例超时、最大重试和分片大小放入第三步的“高级执行策略”，默认值来自资源池与数据集建议。

确认页至少展示：

```text
用例数与预计 Job 数 / 数据集版本摘要 / Runtime 与版本
resolved commit 与资产数量 / 模型与凭据类型 / 资源池与在线容量
并发、超时、重试 / 评分镜像 digest / 指标口径 / 成本估算口径
```

创建按钮是幂等操作；双击或网络重试不得创建两次评测。创建成功跳详情，不依赖创建响应持续等待所有分片派发完成。

### 3.6 评测详情与结果

- 顶部同时呈现执行状态、结果状态与轨迹处理状态；避免“500/500 完成”被理解为全部解决。
- 进度堆叠顺序固定为已解决、未解决、运行中、失败/超时、排队；数值来自同一状态汇总。
- 运行中指标标“快照”，分母与口径就近展示；终态后才显示“最终结果”。
- 用例明细分页默认 20 条，状态计数不受当前页影响；筛选、搜索、页码进入 URL 查询参数以便分享内部深链。用例详情增加测试打点视图，按 F2P/P2P 或数据集检查项分组，失败测试可进入完整日志。
- 重试以新 attempt 执行，保留旧 attempt 的轨迹与评分；重试按钮只出现在可重试终态。
- 达到模型预算时显示“预算已暂停”，而非失败或部分成功；确认增加预算后从未完成用例继续，被打断的旧 attempt 仍可查看。
- 结果对比自动推荐最近的可比评测，并允许手动更换；推荐原因与配置差异和指标 delta 同屏展示。
- 取消需要确认范围、费用与数据保留策略；取消是异步状态，不在点击后直接伪装成已取消。

### 3.7 会话轨迹

保留原型三栏：左会话树、中间 waterfall、右 span 属性。补充三条实现约束：

1. URL 包含 `caseRunId`、`attempt`、`sessionId`、`spanId`，刷新/新窗口恢复同一选中状态。
2. 会话树与 waterfall 使用同一父子证据；仅按时间相邻不能建立父子关系。
3. 右栏分“摘要、消息/输入输出、属性、原始记录”四层；大文本分页/按段加载，thinking 与工具输出按组织策略脱敏。

## 4. 状态矩阵

| 状态 | 页面表达 | 后端要求 |
|---|---|---|
| 空态 | 说明原因、清除筛选或创建入口 | 区分真正无数据与筛选无结果 |
| 加载 | 保留页面骨架和上下文 | 请求可取消，慢请求不覆盖新筛选 |
| 失败 | 页内错误、请求 ID、重试 | 错误码稳定，详情脱敏 |
| 无权限 | 锁定字段与申请说明 | API 返回 403，前端隐藏不是鉴权 |
| 部分成功 | 完成数与失败数并存 | 执行结果与解决结果分别聚合 |
| 危险操作 | 二次确认、影响与费用 | 服务端状态机和幂等键复核 |
| 容量不足 | 在线/上限/排队风险 | 允许排队但给出预期，不承诺秒级启动 |
| 连接不匹配 | 禁用选项和原因 | 保存前再次校验 |
| Ref 未解析 | 阻塞下一步 | resolved commit 是成功前置条件 |
| 轨迹处理中 | 独立进度与重试入口 | 不影响已完成的评分结果 |
| 轨迹降级 | 显示原因与原始文件入口 | 保留 parser 版本和错误摘要 |
| 断线重连 | 非阻塞提示与最后更新时间 | 快照 + 游标回放，事件去重 |

## 5. 原型与生产实现的差异

- 原型用本地 mock 驱动所有状态；生产页面统一从 API 读真实数据，不在业务组件中保留“Stub Provider”分支。
- 原型的“SSE”是交互演示；生产以真实快照和事件流为准。
- 原型部署回滚是状态演示；生产回滚受权限、环境审批和数据库兼容检查约束。
- 原型最低宽度 1080px；MVP 生产可延续桌面优先，但需保证 1280×800 下主操作不被遮挡，移动适配不在本轮范围。
