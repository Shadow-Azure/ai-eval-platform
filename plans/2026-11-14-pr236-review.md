## §1 一页速览

一句话：**把“镜像源”从只读环境变量变成“部署默认 + 管理员覆盖”的双层配置，并让默认值由 GitHub Secrets 随部署注入。**

比喻：部署默认源像公司统一采购清单（GitHub Secrets 定）；管理员在本环境可以临时改顺序/加供应商（DB 覆盖），但清掉覆盖就回到统一清单，不需要去仓库后门改 `.env`。

| 交付块 | 内容 |
|---|---|
| 数据 | `dataset_image_sources_setting`（tenant 唯一，sources_json/updated_by/at） |
| API | GET 返回 default/override/effective；PUT 保存有序覆盖；DELETE 恢复默认 |
| 探测 | `effective_sources` 优先 DB，空则 `DATASET_IMAGE_REGISTRIES`；worker/legacy 共用 |
| 前端 | 设置页排序/启停/增删/编辑/保存/恢复；导入页入口 |
| 部署 | Secret → workflow payload → `write-managed-env.sh` → `.env` → compose api/worker |

## §2 架构导览

### 2.1 双层配置

`dataset_images.py:242` 的 `override_row`/`override_sources` 读单行设置；`effective_sources`（`:269`）在覆盖存在时用它，否则 `configured_sources(settings)`。这样部署默认和运行时覆盖不会互相覆盖，且保存后下一次校验立即生效。

### 2.2 设置 API

`api/dataset_image_sources.py` 的 GET 走 `require_session`，PUT/DELETE 走 `require_admin`；`parse_source_records` 统一校验名称、registry/namespace、重复、空列表和 20 个上限；保存写 `updated_by`。

### 2.3 导入链路

`dataset_imports.py` 的 worker 和 `datasets.py` 的 legacy 导入都调用 `effective_sources(session, settings)` 并传给 `probe_case_images(..., sources=...)`；探测结果仍落在 `image_check`，m8-25 的阻断逻辑不变。

### 2.4 部署链路

`deploy.yml` 把 Secret 放进 job env，payload 写 `DATASET_IMAGE_REGISTRIES=...`；`write-managed-env.sh` 把它作为 managed key 原子写入 `.env`；compose 的 api/worker 用 `${DATASET_IMAGE_REGISTRIES:-docker.io}` 注入。**deploy.sh 不再 set_env 覆盖**（见 §7）。

### 2.5 前端

`DatasetImageSourcesPage.tsx` 用本地列表编辑，PUT 保存、DELETE 恢复；`nav.ts`/`routes.tsx` 挂在 admin 下；导入页“管理镜像源”跳到设置页。默认/覆盖用 `is_default` 标签区分。

## §3 数据流走查

1. 部署：GitHub Secret → workflow payload → `write-managed-env.sh` → `.env` → compose env → `Settings.dataset_image_registries`。
2. 管理员打开 `/settings/dataset-images` → GET 返回 defaults/override/effective → 编辑 → PUT 写 DB → 下一次导入 worker 读 DB。
3. worker 校验 → `effective_sources` → `probe_case_images` → `image_check.sources` 顺序反映设置页。
4. DELETE → DB 行删除 → 下次 GET/worker 回退 env 默认。

## §6 讨论点

### 6.1 全部源停用是否允许保存

- **位置**：`DatasetImageSourcesPage.tsx`。
- **现象**：后端允许所有源 `enabled=false`；导入会被阻断。
- **问题**：管理员可能误操作，保存后所有导入失败。
- **预判**：UI 应阻止/警告；后端仍保留“全停用=阻断”的语义，供排障。
- **结论**：已加 warning 并禁用保存（§7）。

### 6.2 默认源 Secret 的输入安全

- **位置**：`deploy/write-managed-env.sh`。
- **现象**：Secret 原样写入 `.env`。
- **问题**：如果 Secret 含换行，可能注入额外 env key。
- **预判**：应在 workflow 拒绝多行 Secret；不要让 `.env` 写入任意行。
- **结论**：已加单行校验（§7）。

### 6.3 设置覆盖与部署默认的审计

- **位置**：`dataset_image_sources_setting`。
- **现象**：只保留当前覆盖的 updated_by/at；DELETE 后审计丢失。
- **问题**：谁在何时恢复默认不可追溯。
- **预判**：当前规模可接受；后续可加审计事件/历史表。
- **结论**：（待讨论）
