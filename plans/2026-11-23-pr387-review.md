## §1 一页速览

一句话：把「谁内容长谁就抢宽」的自动表格，改成「每列先量好宽度、内容超长就省略」的固定表格。

比喻：原来的表格像一排没有隔板的书架，最厚的一本书横着放，就把旁边格子挤没了；现在每列都有固定宽度的隔板，书太长只在格子里显示省略号，鼠标悬停再看全名。

| 交付块 | 结论 |
|---|---|
| 桌面 1500×837 | 行高 332px → 71px；模板列 658px → 240px；固定组合列 71px → 300px |
| 长文本 | 名称单行省略、描述两行、组合三行省略，均有 `title` |
| 窄屏 1280×837 | 内容区 978px，表格 1180px，横向滚动，列宽不塌 |
| 原型 | 同步 8 列（新增费用估算），同数据同视口效果一致 |
| 接口 / 启动弹层 | 在修复后的列表上均可正常打开 |
| CI | `flow-offline`、`flow-online`、`docs`、`web`、`runner`、`deployment` 全部通过 |

验证基线：本机 Vite + mock 控制面，Chrome headless，1500×837 @2x 与 1280×837 @2x，浅色主题；截图见 PR #387 描述与 release `m10-386-template-layout-evidence-20261123`。

## §2 架构导览

### 2.1 生产表格：先定宽度，再谈内容

`web/src/pages/EvalTemplatesPage.tsx:306-310` 给 antd `Table` 加了 `tableLayout="fixed"` 与 `scroll={{ x: 1180 }}`。这一步是根因修复：antd 默认 `table-layout: auto`，浏览器会按内容的最小宽度反推列宽；固定组合列里没有可断行的短词，最终被压到 71px。

`web/src/pages/EvalTemplatesPage.tsx:103-206` 给 8 列都声明了百分比宽度：

| 列 | 宽度 |
|---|---|
| 模板 | 20% |
| 固定组合 | 25% |
| 状态 | 8% |
| 最近启动 | 10% |
| 累计启动 | 7% |
| 费用估算 | 7% |
| 更新 | 7% |
| 操作 | 16% |

百分比宽度配合 `scroll.x: 1180` 的行为是：容器宽于 1180 时表格撑满容器，百分比按实际宽度分配；容器窄于 1180 时表格保持 1180 最小宽度，出现横向滚动。1500 视口实测 1198px，1280 视口实测 1180px + 滚动。

### 2.2 三类长文本：各用各的截断

- 名称：`web/src/styles/templates.css:65-82` 把 antd `Button` 改成 `display:block; width:100%; overflow:hidden; white-space:nowrap; text-overflow:ellipsis`，并处理 antd 内部 `<span>`。`EvalTemplatesPage.tsx:115` 把完整名称放进 `title`。
- 描述：`templates.css:84-90` 用 `-webkit-line-clamp: 2` 限制两行；`EvalTemplatesPage.tsx:120` 挂 `title`。
- 固定组合：`templates.css:107-111` 每行 `nowrap + overflow:hidden + text-overflow:ellipsis`；`EvalTemplatesPage.tsx:131-149` 先把三行文本拼成字符串，既用于渲染也用于 `title`，避免标题与可见文本不一致。

### 2.3 行高与操作列

`templates.css:92-105` 把单元格改为顶部对齐、上下内边距 6px，并把表格内小按钮的左右内边距压到 6px。这样名称/描述不再垂直居中悬空，操作按钮也不会逐字换行。

注意：管理员行有 4 个按钮（详情/接口/停用/启动），16% 宽度下「启动」会换到第二行；实测行高 71px，与 issue 建议效果的 74px 同一量级，仍远低于修复前的 332px。这是有意的取舍，见 §6 D1。

### 2.4 原型：把生产多出来的费用列补进设计

`prototype/app.js:644-649` 给 3 条种子模板补 `costEstimate`；`prototype/app.js:739-740` 给生成的 20 条变体补费用估算（部分留空以展示「未填写定价」）。`prototype/app.js:1336-1339` 新增费用单元格，`prototype/app.js:3507` 新增表头列。

`prototype/styles.css:4601-4631` 把 7 列宽度改成 8 列 20/25/8/10/7/7/7/16；`prototype/styles.css:4648-4664` 把描述从单行改为两行 clamp，把组合行从 flex 改为 block + 省略号；`prototype/styles.css:4751-4753` 在窄屏同时隐藏费用列的 `th` 与 `td`，修掉旧代码只隐藏 `th` 的错位隐患。

`prototype/index.html` 由 `node prototype/build-standalone.mjs` 重建，未手改。

## §6 讨论点

### D1 操作列 16% 下「启动」换到第二行

- **位置**：`web/src/pages/EvalTemplatesPage.tsx:203-206`、`web/src/styles/templates.css:103-105`
- **现象**：管理员行有 4 个按钮，16%（1500 视口约 192px）下「详情/接口/停用」在第一行，「启动」在第二行；行高 71px。
- **问题**：原型的 3 个按钮在一行内；生产多一个管理员启停按钮，因此多一行。是否应该把操作列加到 18%（约 216px）让 4 个按钮同行，代价是名称列从 20% 降到 18%、名称显示更短。
- **预判**：当前 71px 已满足 issue「行高 74px 左右、按钮不逐字换行」的验收；把操作列加宽会牺牲名称可读性，且原型没有管理员启停按钮，无法完全对齐。建议保持现状，若产品更在意单行操作再单独调整。
- **结论**：（留空给用户拍板）

### D2 没有自动化视觉回归

- **位置**：`web/src/pages/EvalTemplatesPage.tsx:306-310`、`web/src/styles/templates.css:65-111`
- **现象**：本次以脚本化截图 + DOM 测量验证；仓库当前没有 Playwright 或其他浏览器测试依赖。
- **问题**：名称长度变化仍可能再次触发列宽/截断问题，缺一条自动回归。
- **预判**：新增 Playwright 会引入前端测试框架、CI 浏览器和截图基线，属于独立基础设施改动；本次先把 1500×837 / 1280×837 的截图场景留在冒烟报告，后续可复用为 Playwright 用例。不阻塞本 PR。

### D3 保留费用估算列并同步原型

- **预判**：保留列可以提前发现未定价模板，且不丢失生产已有信息；若产品最终决定列表不展示成本，再单独从 web 和原型移除该列，回到 7 列。不是本 PR 的缺陷。

## §9 文件级代码分析

### 9.1 `web/src/pages/EvalTemplatesPage.tsx`

**职责**：评测模板列表页；本次把列定义从「6 列固定 px + 2 列无宽度」改成「8 列百分比 + 固定布局」。

变更前（旧）：
```tsx
<Table rowKey="id" size="small" ... />
...
{ title: "模板", key: "name", render: ... }          // 无 width
{ title: "固定组合", key: "combo", render: ... }      // 无 width
{ title: "状态", width: 130 }
...
{ title: "操作", width: 250 }
```

变更后（新）：
```tsx
<Table tableLayout="fixed" scroll={{ x: 1180 }} ... />
{ title: "模板", width: "20%", className: "template-name-cell" }
{ title: "固定组合", width: "25%", className: "template-combo-cell" }
...
{ title: "操作", width: "16%" }
```

实现思路：先让浏览器不再按内容反推列宽，再给每列明确份额；固定组合列拿到 25% 后，三行内容才有空间做单行省略。`title` 让截断不丢信息。

检视发现：无阻塞问题。操作列换行见 D1。

### 9.2 `web/src/styles/templates.css`

**职责**：列表的截断、对齐与紧凑化。

关键依赖：antd `Button` 的 `.ant-btn` 自带 `white-space: nowrap`。旧代码只把按钮改成 link，没有覆盖 `white-space` 和宽度，所以长名称仍按 640px 最小宽度撑开列。新代码在 `.template-name-link` 上 `display:block; width:100%; overflow:hidden; white-space:nowrap; text-overflow:ellipsis`，并给内部 `<span>` 同样的约束。

旧/新对照：
```css
/* 旧 */
.template-name-link { height: auto; padding: 0; font-weight: 650; text-align: left; }

/* 新 */
.template-name-link { display:block; width:100%; overflow:hidden; text-overflow:ellipsis; white-space:nowrap; ... }
.template-name-link > span { display:block; overflow:hidden; ... }
.template-name-desc { display:-webkit-box; -webkit-line-clamp:2; ... }
.template-combo-line { overflow:hidden; white-space:nowrap; text-overflow:ellipsis; }
```

检视发现：`-webkit-line-clamp` 是 WebKit 前缀属性，但当前 Chromium/Edge/Safari 均支持；`line-clamp` 作为标准属性一并写上。无阻塞问题。

### 9.3 `prototype/app.js` 与 `prototype/styles.css`

**职责**：让原型与生产保持同一 8 列设计。

变更点：
- 新增 `costEstimate` 数据：种子 3 条 + 生成 20 条变体；
- 表头与行各加一个「费用估算」单元格；
- 8 列宽度 20/25/8/10/7/7/7/16；
- 描述两行 clamp，组合行改 block 省略；
- 窄屏隐藏费用列的 `th` 与 `td`，修掉旧代码只隐藏 `th` 的错位。

检视发现：原型数据是演示数据，费用值不是真实报价；原型 README 已说明所有业务数据在浏览器本地，属于预期。无阻塞问题。
