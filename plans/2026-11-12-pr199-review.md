## §3 数据流走查

1. **启动**：`AppRoutes` 把 `AppShell` 作为布局路由（`web/src/app/routes.tsx:25`）→ `AppShell` 渲染 → `useState(readSidebarCollapsed)` 读 `ep.sidebar.collapsed` → 为 `"1"` 则首帧带 `sidebar-collapsed` 类（`AppShell.tsx:19`、`:37`）。
2. **布局**：`.app-shell` 上的 `--sidebar-width` 变 72px → `.sidebar` 宽度 72px、`.main-shell` 左边距 72px（`shell.css:6-8`、`:14`、`:286`），两者同一变量、同一 180ms 过渡，不会中途错位。
3. **切换**：鼠标点击、`Tab` 聚焦后 `Enter`/`Space` 都会触发原生 `button` 的 click → `onToggle` → `toggleSidebar` 取反 → 写 `localStorage`（`AppShell.tsx:26-34`）。
4. **收起渲染**：`Sidebar` 收到 `collapsed=true` → 文案节点被 CSS 隐藏，导航项被 antd `Tooltip` 包裹，当前页仍保留 `NavLink` 的 `aria-current="page"` 与 `.active` 类；`shell.css:259-262` 把左侧竖条移到贴边位置。
5. **路由切换**：`AppShell` 是布局路由，切页面时 `Sidebar` 不重挂载，`sidebarCollapsed` 状态天然保留；`localStorage` 也不会被重读。
6. **刷新**：回到第 1 步，读到上次的值。
7. **异常**：`localStorage` 被禁用时 `readSidebarCollapsed` 捕获异常返回 `false`（展开），切换仍生效但不持久（`AppShell.tsx:9-15`、`:29-33`）。

**例子**：用户收起导航 → 打开 `/evals/xyz` 看详情 → 侧栏仍是 72px 图标栏；按 F5 → 仍是 72px；换一台电脑或隐身窗口 → 236px（默认展开）。

## §6 讨论点

### 6.1 收起态标签不随键盘聚焦出现（P2）

- **位置**：`web/src/components/Sidebar.tsx:70`（HEAD）；`.agents/flow/issues/m8-09-collapsible-sidebar.md:50`
- **现象**：`Tooltip` 没有传 `trigger`，antd 经 `rc-tooltip` 的默认值是 `['hover']`（`web/node_modules/rc-tooltip/lib/Tooltip.js:25`），而 focus 只在 action 含 `focus` 时才绑定（`web/node_modules/@rc-component/trigger/lib/index.js:415`）。因此 `Tab` 到收起态图标只有 focus 轮廓，没有名称浮层；原型用的原生 `title` 同样不响应 focus。检视结束前工作树已出现加上 `trigger={["hover", "focus"]}` 的未提交改动（非本检视所为）；若它随 PR 提交，本项可关闭。
- **问题**：issue 前端设计表写的是「仅图标，居中；悬停或聚焦显示标签」（英文侧 `:50` 为 "label on hover or focus"），而验收文字只写了「悬浮标签」；实现只满足后者。对不用读屏的纯键盘用户，一排无标签图标无法辨认，这是收起态核心场景的可访问性缺口。
- **预判**：补 `trigger={["hover", "focus"]}` 即可（`NavLink` 已是 `forwardRef`，focus 事件从 `<a>` 冒泡），或收起态统一用 `aria-label` + 视觉浮层；建议同时把 `09` 文档补上 focus 语义。
- **结论**：（留空）

### 6.2 PR 描述与 issue 文档仍停留在「只改设计」（P2，文档/流程）

- **位置**：PR #199 描述正文与「已知限制」段；`.agents/flow/issues/m8-09-collapsible-sidebar.md:39`、`:83`（英文侧 `:39`、`:83`）
- **现象**：PR 描述写「**本 PR 不修改生产前端 `web/`，也不改后端**；方向确认后再进入实现」，已知限制又写「仅评审设计，生产 `web/` 与后端未改动」；issue 文档写「先交付设计、原型和修改前后截图，确认方向后再改生产前端」「本次只评审设计，不改生产前端」（以上为 HEAD 状态；工作树中 issue 双语文案已改为「设计与实现同一 PR」，但 PR 描述与标题仍未更新）。但 HEAD 的 `5a9acd0` 改了 `AppShell.tsx`、`Sidebar.tsx`、`Icon.tsx`、`shell.css`、`tokens.css` 五个生产文件，PR 标题也仍是 `docs(m8-09)`，实现 commit 却是 `feat(m8-09)`。

### 6.3 收起态租户信息只剩 `title`（P3，可访问性）

- **位置**：`web/src/components/Sidebar.tsx:95-104`；`web/src/styles/shell.css:279-281`
- **现象**：收起态 `.tenant-copy` 被 `display: none`、头像 `aria-hidden="true"`、箭头也隐藏，租户名只存在于 `<div class="tenant-chip" title="租户 … · …">` 上；`div` 不可聚焦，`title` 在多数读屏里也不会成为无障碍名称。
- **问题**：读屏用户和键盘用户收起后拿不到「当前租户」；展开态顶部 Header 仍显示租户，所以不是完全丢失。issue 设计明说「仅头像，title 提供完整信息」，属于设计已接受的取舍。
- **预判**：若要补，给 chip 加 `aria-label`（或 `tabIndex={0}` + `aria-label`）；不补也说得过去，但建议在 issue 的已知限制里记一笔。
- **结论**：（留空）

### 6.4 切换按钮的 `title` 与可见文案重复，且 tooltip 机制不统一（P3，UX）

- **位置**：`web/src/components/Sidebar.tsx:89-90`，对比 `:70`
- **现象**：展开态按钮已经显示「收起导航」，`title` 再弹一次同义的原生 tooltip；收起态导航项用 antd `Tooltip`（带样式、可跟随主题），按钮和租户区却用原生 `title`（约 1s 延迟、样式由浏览器决定、键盘不可见）。
- **问题**：同一个侧栏里两套 tooltip 机制，体验不一致；展开态的原生提示属于重复信息。
- **预判**：展开态去掉 `title`（保留 `aria-label` 即可），收起态按钮改用 antd `Tooltip` 并复用导航项的 trigger 配置；一次改动能同时收掉 6.1 和本条的一半。
- **结论**：（留空）

### 6.5 收起态 tooltip 的 `aria-describedby` 与 `aria-label` 同文（P3，读屏可能重复）

- **位置**：`web/src/components/Sidebar.tsx:62`、`:70`；`web/node_modules/rc-tooltip/lib/Tooltip.js` 的 `getChildren`
- **现象**：`rc-tooltip` 会给子元素设置 `aria-describedby` 指向浮层内容，而浮层内容与 `aria-label` 是同一个字符串；浮层未打开时该 id 尚未挂载。
- **问题**：tooltip 打开时读屏可能读成「评测任务，评测任务」；未打开时 `aria-describedby` 指向不存在的节点（多数 AT 会忽略，但属于噪声）。
- **预判**：可接受，不必为此改结构；若在意，浮层内容改成补充信息（如「前往评测任务」）而不是重复名称。
- **结论**：（留空）

### 6.7 验收要求 1440 与 1280 两个视口，证据只有 1440（P3，证据缺口）
