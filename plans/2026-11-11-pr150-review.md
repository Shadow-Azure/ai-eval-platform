## §1 一页速览

一句话：**把线上退化成 5 列表格的 `/datasets` 恢复成由后端适配器注册表驱动的卡片目录，并补齐筛选、分页、统计和适配器规范入口。**

## §3 数据流走查

1. 用户登录后进入 `/datasets`；页面并行请求 `/api/v1/datasets?limit=200&offset=…`、`/api/v1/dataset-adapters`、`/api/v1/dataset-imports?limit=3`（`DatasetsPage.tsx:267-278`）。
2. 目录接口按页返回聚合条目；前端循环到 `has_more=false`（`datasets.ts:299-310`），保证 >200 时统计与筛选仍完整。
3. `datasetCards()` 对每个条目：若适配器未注册 → planned；最新版本 active → ready；否则 draft（`DatasetsPage.tsx:106-138`）。已注册但没有数据集的适配器追加一张 planned 卡片（`:140-160`）。
4. 统计卡从全量卡片算：目录类型、ready 数、最新版本用例数之和、待接入（draft + planned）。
5. 筛选：任务族 Tab → 状态 Select → 搜索关键字，过滤后按状态、用例数、名称排序；页码越界时 `currentPage = min(page, pageCount)`（`:303-327`）。
6. 卡片动作为「查看详情 / 继续导入 / 查看适配计划」；弹窗读取 `/dataset-adapters` 的指标键、主指标与 `case_visibility`，不写死 SWE-bench。
7. 最近导入从 `/dataset-imports` 读取，显示用例数、校验失败数与相对时间。

## §6 讨论点

### 6.1 最新版本为 archived 时被显示成“待导入”

- **位置**：`backend/app/services/datasets.py:550`、`web/src/pages/DatasetsPage.tsx:106-112`
- **现象**：`DatasetVersion.status` 的闭集包含 `active/archived`，但只有 `active` 映射为 ready；若最新版本是 archived，目录会显示“待导入 / 继续导入”。
- **问题**：语义不准确，归档数据集并不是“还没导入”。
- **预判**：当前没有任何归档 API 或工作流，`DATASET_VERSION_STATUSES` 的 archived 分支不可达；若为此新增第 4 种产品状态，会超出 #141 的三状态词表，属于未经确认的产品决策。
- **结论**：接受为未来边界。在聚合处加注释说明“非 active 暂按待导入处理，引入归档工作流时再定义 CTA”；本次不新增产品状态。

### 6.2 适配器元数据在 Protocol 中是必填，运行时却用 getattr 回退

- **位置**：`backend/app/datasets/__init__.py:79-95` 与 `:100-121`
- **现象**：Protocol 声明 `display_name` 等必填，`adapter_metadata()` 却允许旧适配器缺失。
- **问题**：类型契约与运行时行为不一致，读者会误以为第三方适配器必须实现。
- **预判**：当前仓库只有 SWEBenchAdapter，平台适配器应实现这些字段；getattr 是防御性兜底而非首选契约。
- **结论**：已补注释说明“平台适配器应声明，第三方/旧适配器由 getattr 兜底”。不改 Protocol 结构，避免为假想旧适配器拆出第二套类型。

### 6.3 目录一次拉取 200 行会截断统计

- **位置**：`web/src/api/datasets.ts:299`、`web/src/pages/DatasetsPage.tsx:303`
- **现象**：原实现固定 `limit=200`，>200 个数据集时统计卡与分页只看前 200 行。
- **问题**：违反 #141“统计卡数字与目录实际数据一致”。
- **预判**：目录规模当前远小于 200，但这是会随数据增长暴露的真实缺陷。
- **结论**：已修复为按 `has_more/next_offset` 循环拉取，最多 50 页防御后端异常；统计与分页仍在前端组合，规模再大时应改为服务端筛选/分页。

### 6.4 任务族“Tab”缺少选择语义

- **位置**：`web/src/pages/DatasetsPage.tsx:468`
- **现象**：按钮只有 `.active` CSS 类，屏幕阅读器无法知道当前选中项。
- **问题**：可访问性缺陷，纯样式状态不等于语义状态。
- **预判**：不影响鼠标用户，但属于低成本可修项。
- **结论**：已补 `aria-pressed`；未改成完整 tablist，因为当前交互是“筛选按钮组”而非键盘方向键切换的页签。

### 6.5 planned / draft 在真实数据中不可达

- **位置**：`DatasetsPage.tsx:140-160`、`tests/backend/test_dataset_catalog.py` 的待导入用例
- **现象**：当前注册表只有 swebench 且有数据集，planned 卡片为 0；真实导入只在成功时创建数据集行，draft 也不可达。
- **问题**：两条状态路径缺少真实数据验证。
- **预判**：这是产品当前形态，不是实现缺陷；伪造第二个适配器或“先登记后导入” API 会超出 #141。
- **结论**：接受。冒烟用 SQLite fixture 行验证待导入卡片；planned 卡片逻辑由组件代码与适配器目录测试覆盖，等第二个适配器落地后补浏览器场景。

### 6.6 本地 SQLite 丢失时区，截图相对时间为“8 小时前”

- **位置**：`backend/app/services/datasets.py:508-585` 的 `_iso()` 与冒烟数据
- **现象**：SQLite 返回 naive 时间，浏览器按本地时区解释；生产 PostgreSQL 返回带偏移时间。
- **问题**：只影响本地证据截图，不是生产行为。
- **预判**：不应为本地 fixture 改生产时间契约。
- **结论**：接受并在冒烟报告里标注；生产冒烟时复核相对时间。
