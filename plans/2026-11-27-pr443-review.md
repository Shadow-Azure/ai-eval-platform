## §1 一页速览

一句话：Runner 以前把 egress token 放在 Basic 用户名位、密码留空，Squid 看到空密码直接 407；本 PR 在密码位补一个非空占位符 `x`，让 Squid 走到 helper，helper 仍只校验用户名位 token。

比喻：Squid 像门卫，Basic 凭据是「姓名 + 口令」。旧实现只报姓名、口令栏空着，门卫按规则直接拒；修复不是换姓名，而是把口令栏填成 `x`，门卫才愿意把姓名交给登记员（helper）核对。

| 交付块 | 内容 |
| --- | --- |
| 行为 | 有 token 时生成 `http://<token>:x@<host>:<port>`；无 token 时保持不带凭据的私网 URL |
| 回归 | Runner URL 密码段非空断言；helper 对 `<token> x` 返回 `OK` |
| 文档 | 中英架构文档、Squid 配置注释、helper docstring 统一契约 |
| 流程 | 新增 m8 issue 条目，状态 `in-progress`，合并后随闭环提交置 `done` |

## §2 架构导览

### 2.1 Runner 侧 URL 组装

`runner/scripts/real-task.mjs:280-305`：`EGRESS_PROXY_PASSWORD` 固定为 `"x"`；`credentialedEgressProxy()` 在 token 存在时拼成 `${protocol}//${token}:x@${authority}`。`egressProxyEnvArgs()`（`real-task.mjs:330-335`）把结果同时写入 `HTTPS_PROXY` 与 `HTTP_PROXY`，并继续用 `egressNoProxy()` 生成 `NO_PROXY`。无 token 时 `credentialedEgressProxy()` 原样返回 payload 的私网 URL（`real-task.mjs:296`），行为与旧版一致。

### 2.2 代理侧 Basic 解码

`deploy/proxy/squid.conf:40-50` 用 `auth_param basic program` 调 helper，并只要求 `proxy_auth REQUIRED`；`deploy/proxy/egress_auth.py:84-96` 从每行 `username password` 里只取用户名，调用 `_verify()` 校验 v1 签名、`exp` 与 `scope=egress`。空密码根本到不了 `main()`：Squid 在 Basic 解码阶段把凭据标成 `AUTH_BROKEN`，直接 407。这就是 issue #442 里「token 完整、仍然 407」的机制。

### 2.3 文档与流程契约

`docs/architecture.md:67,71,78-80` 与英文侧逐项镜像，把「密码留空」改成「密码位非空占位符」；`scripts/doc-budgets.manifest.json` 记录 +50 词的理由。`.agents/flow/issues/m8-egress-proxy-empty-password.*` 的 yaml 围栏两侧逐字节一致，`github.number` 指回 #442。

## §3 数据流走查

1. 平台按 `scope=egress` 签发短期 token，和 `egress_proxy` 一起放进分片 payload（本 PR 未改）。

- 位置：issue #442「修复建议」的 P1（固定 Squid 镜像、CI 真实 Squid 集成测试、部署带 token 的 CONNECT）与 P2（407 诊断、访问日志脱敏 token）。

## §9 文件级代码分析

### `runner/scripts/real-task.mjs`（M）

职责：把 payload 的 `egress_proxy` / `egress_token` 组合成容器可用的代理环境变量。

变更代码块：

```js
// 旧
return `${parsed.protocol}//${token}:@${authority}`;
// 新
const EGRESS_PROXY_PASSWORD = "x";
return `${parsed.protocol}//${token}:${EGRESS_PROXY_PASSWORD}@${authority}`;
```

这在做什么：只填空密码位，不改 token 位置、端口推导和异常回退。为什么这么写：Squid 的 Basic 解码在调用 helper 前就拒绝空密码，因此密码必须是「非空但无意义」的占位符；用常量而不是字面量，方便测试与后续说明。

检视发现：无。`new URL()` 失败时仍回退原 proxy；`normalizeEgressToken()` 的白名单保证 token 不需要转义。

### `tests/runner/real-task-runtime-setup.test.mjs`（M）

职责：用 fake `docker` 记录最终 exec 参数，断言代理环境变量。

变更代码块：

```js
const EGRESS_PROXY_WITH_TOKEN = `http://${EGRESS_TOKEN}:x@10.0.0.10:3128`;
...
const credential = new URL(value);
assert.notEqual(credential.password, "", `empty Basic password in ${value}`);
```

这在做什么：既锁定完整 URL，又显式断言密码非空；旧实现的 `:@` 会在第一处断言失败。为什么这么写：只断言字符串已经足够回归，但显式密码断言让失败信息直接指向根因。

检视发现：无。测试仍覆盖 install + agent 两个 exec 点，无 token 分支另有独立用例。

### `tests/deploy/egress-proxy.test.mjs`（M）

职责：验证 helper 的 token 校验契约。

变更代码块：

```js
test("egress_auth.py ignores the non-empty placeholder password (#442)", () => {
  const token = issueToken(egressClaims());
  assert.deepEqual(checkCredentials([`${token} x`]), ["OK"]);
});
```

这在做什么：把真实的 `token x` 线路格式喂给 helper，证明密码值不参与校验。为什么这么写：防止后来者误以为密码需要参与签名或必须为空。

检视发现：无。该测试只覆盖 helper 的容忍度，Squid 的空密码拒绝由手工冒烟覆盖（见 §6.3）。

### `deploy/proxy/squid.conf`（M）与 `deploy/proxy/egress_auth.py`（M）

职责：说明并维持「用户名位 token、密码位非空占位符」的契约。

+ egress token in the Basic username slot. The password slot

检视发现：无。`egress_auth.py` 的可执行权限与行协议未变。
