## §1 一页速览

**一句话**：停用模板不再占着禁用的「启动」，而是显示可执行的「启用 / 删除」；删除走确认浮窗，删的是模板本身，评测与轨迹不跟着消失。

**一个比喻**：模板像一张「点菜单」，评测记录是厨房已经做完的菜。以前菜单上留着一道划掉的菜还占着位置；现在停用的菜单只留「重新上架」和「撕掉菜单」两个动作，撕掉菜单不会把已经上桌的菜一起倒掉。

**交付块**

| 块 | 内容 |
|---|---|
| 停用行操作区 | 「启用」+ 红色「删除」，不再渲染禁用「启动」 |
| 快速启动 | 与列表复用同一组件，停用行同样显示「启用 / 删除」 |
| 删除确认 | 标题带模板名，说明不可恢复、历史保留、固定组合与累计启动 |
| 删除结果 | 取消不变；确认后行消失、toast、筛选空态；运行记录保留 |
| 后端语义 | `delete_template` 只删模板行，`EvalRun.template_id` 与版本保留 |
| 回归 | 后端删除 + 运行保留测试；浏览器交互断言与前后截图 |

**验证基线**：`pytest tests/backend` 全绿（1 skip）；`web npm run build` 通过；`npm test` 127；`verify:docs`、`lint:docs`、`verify:flow`、`verify-flow --diff` 通过；浏览器 1500×1100 @2x 交互断言通过。CI 的 docs / flow-offline / flow-online / backend / web / runner / deployment 全部通过（Project 关联后 flow-online 重跑通过，见 §6.4）。

## §2 架构导览

### 2.1 共用操作渲染层

`web/src/components/TemplateActions.tsx:24` 是列表与快速启动的唯一按钮渲染入口。组件内部按 `template.enabled` 分流：停用且管理员时渲染「启用 / 删除」（`TemplateActions.tsx:71-122`），启用时渲染可选的「停用」和「启动」（`TemplateActions.tsx:124-141`）。这样两个入口不会各自长出一套按钮逻辑，符合 issue 里「快速启动行与完整列表复用同一个操作按钮渲染」的要求。

### 2.2 数据刷新边界

所有写操作共用 `["eval-templates"]` 查询前缀刷新（`TemplateActions.tsx:34-36`）：列表查询 key 是 `["eval-templates", "list", ...]`（`EvalTemplatesPage.tsx:29-31`），快速启动 key 是 `["eval-templates", "quick-launch"]`（`EvalsPage.tsx:102-104`）。因此从任一入口启用或删除后，另一个入口下一次读取也会拿到新数据，不需要页面间手工传状态。

### 2.3 后端删除语义

`backend/app/services/eval_templates.py:588-599` 现在只做 `get_template` + `session.delete`。`EvalRun.template_id` 在 `backend/app/models/evaluation.py:154` 是无外键的字符串，运行记录不会级联删除；`template_briefs()`（`eval_templates.py:816-849`）对已删除模板自然返回空，评测列表与详情只失去模板名解析，不会读不到运行本身。

## §3 数据流走查

1. 用户打开 `/evals/templates`，列表请求 `GET /api/v1/eval-templates?status=disabled`；停用行渲染 `TemplateActions`。
2. 点击「启用」→ `updateEvalTemplate(id, {enabled:true}, version)` → 成功后 toast 并刷新 `["eval-templates"]`；停用筛选下该行因服务端过滤而移出。
3. 点击「删除」→ 打开 `Modal`（`TemplateActions.tsx:81-119`），标题、固定组合、累计启动来自当前 `EvalTemplate` 视图，不发额外请求。
4. 点击「取消」→ 仅 `setDeleteOpen(false)`，不发请求，行与计数不变。
5. 点击「确认删除」→ `deleteEvalTemplate(id)` → 204 → toast、关闭浮窗、刷新列表与快速启动。
6. 后端 `delete_template` 删除 `eval_template` 行；已有 `eval_run` 的 `template_id` / `template_version` 保留，`GET /api/v1/evaluations/{run_id}` 仍返回 200，`template` 为 `null`。

## §6 讨论点

### 6.1 删除后评测来源标签消失

**位置**：`backend/app/services/eval_templates.py:588-599`、`backend/app/services/evaluations.py:1100-1110`。

**现象**：删除模板后，运行记录仍保存 `template_id`、`template_version` 与启动快照，但 `template_brief()` 找不到模板，评测详情里的来源模板为 `null`，列表不再显示「来自模板」链接。

**问题**：历史评测保留的是「不可变快照」，是否应该从 `template_snapshot_json` 回退显示模板名，而不是完全失去来源标签？

**预判**：本 issue 只要求「评测记录与轨迹保留」，不要求删除后仍显示模板名；快照回退是一个独立的小改进，涉及列表批量解析与快照字段契约，建议单独开 issue 评估，不在本 PR 扩大接口面。

**结论**：

### 6.2 后端未强制「只能删除停用模板」

**位置**：`backend/app/api/eval_templates.py:223-232`、`web/src/components/TemplateActions.tsx:71-80`。

**现象**：UI 只在停用行渲染删除入口，但 DELETE 接口本身对启用模板也返回 204，未做状态校验。

**问题**：是否需要服务端兜底，避免绕过 UI 误删启用模板？

**预判**：删除接口在 #378 已存在且原本允许删除启用模板（仅拦截有运行的模板），本 PR 没有新增绕过路径；issue 的非目标是「不在启用模板上提供入口」，属于 UI 约束。若后续要收紧 API，应作为独立契约变更并补 409 行为与客户端提示。

**结论**：

### 6.3 删除确认文案的「已停用」前提

**位置**：`web/src/components/TemplateActions.tsx:97-102`。

**现象**：浮窗正文固定写「该模板已停用」，因为入口只出现在停用行；如果以后 API 客户端或复用组件允许从启用状态打开，文案会与事实不符。

**预判**：当前入口与状态严格绑定，这不是现实缺陷；若未来复用该浮窗，应把文案改为根据 `template.enabled` 生成。

**结论**：

### 6.4 flow-online：PR 未关联 Project

**位置**：GitHub PR #426 侧栏 Project；`.github/workflows/flow-gates.yml` 的 flow-online job。

**现象**：flow-online 日志为「PR 未关联 project（GitHub 侧栏设置）」；同一 run 的 flow-offline、docs、backend、web 等均通过。

**问题**：机器人账号的 gh token 只有 `gist / read:org / repo / workflow`，没有 `read:project` / project 写入权限，无法自行把 PR 加入 Projects v2；这是仓库外的流程配置项，不是代码缺陷。

**预判**：需要维护者在 GitHub 侧栏把 PR #426 加入「评测模板与快速启动」Project；关联后重跑 flow-online 即可。与 #400/#103/#120 等历史 PR 的同类情况一致。

**结论**：2026-11-23 维护者已把 PR #426 加入「评测模板与快速启动」Project；重跑 flow-online 通过。不修改代码。

## §9 文件级代码分析

### 9.1 `web/src/components/TemplateActions.tsx`（A）

**职责一句话**：把「停用模板可启用 / 删除、启用模板可停用 / 启动」的按钮、确认浮窗和刷新逻辑收在一个组件里，列表与快速启动共用。

**关键依赖解读**：`@tanstack/react-query` 提供 `useMutation` 与查询失效；antd 提供 `Button` / `Modal` / `Popconfirm` / `Descriptions` / `Alert`。两者都是仓库现有依赖，没有新增包。

**变更代码块分析**

- 旧：列表页自己维护 `toggle` mutation（原 `EvalTemplatesPage.tsx:86-96`），停用行仍然渲染禁用「启动」（原 `:219-243`）；快速启动页也各自渲染启动按钮并单独处理禁用态（原 `EvalsPage.tsx:307-319`）。
- 新：`toggle`、`remove` 与删除浮窗进入组件；停用且管理员时只渲染「启用 / 删除」，否则回退为禁用启动（`TemplateActions.tsx:71-80`）。启用分支保留「停用」Popconfirm，`allowDisable` 让快速启动不重复出现停用入口（`:124-141`）。
- 实现思路：用「启用状态」而不是「页面」决定按钮集合；用统一查询前缀而不是页面回调同步状态。

**检视发现**：删除成功后的关闭依赖 mutation 的 `onSuccess`，若组件在请求期间被列表刷新卸载，React 18 不会报错；没有实际缺陷。

### 9.2 `web/src/pages/EvalTemplatesPage.tsx`（M）

**职责一句话**：模板列表页；本次把操作列的后半段交给 `TemplateActions`，并删掉页内 toggle。

**变更代码块分析**

- 旧：`useMutation` + `Popconfirm` + 双分支按钮都在列定义里，启用和停用走同一个 `toggle.mutate(row)`。
- 新：列定义只保留「详情 / 接口 / 历史」，其余交给 `<TemplateActions ... allowDisable canLaunch={isAdmin} />`（`:207-217`）。`templateQueries.all` 只剩 `list`，因为失效改由组件统一前缀处理。
- 实现思路：页面负责列与弹窗目标状态，组件负责行级写操作。

**检视发现**：无。

### 9.3 `web/src/pages/EvalsPage.tsx`（M）

**职责一句话**：评测任务页；快速启动区改用共用操作组件。

**变更代码块分析**

- 旧：快速启动行直接渲染「启动」，停用模板只能看到一个禁用的启动按钮。
- 新：引入 `useAuth` 取管理员角色，渲染 `<TemplateActions canManage={isAdmin} canLaunch onLaunch={...} />`（`:311-319`）。`canLaunch` 保持快速启动原有的可启动行为，不因角色改变。
- 实现思路：让快速启动与完整列表在「模板能否操作」上使用同一判断。

**检视发现**：非管理员在快速启动仍可打开启动弹窗，这是改动前行为；本 PR 没有改变启动权限，弹窗内的 `canLaunch` 校验仍由服务端和 `TemplateLaunchModal` 负责。

### 9.4 `backend/app/services/eval_templates.py`（M）

**职责一句话**：模板服务；本次把删除从「有运行就拒绝」改为「只删模板行」。

**变更代码块分析**

- 旧：`delete_template` 先统计该模板的 `EvalRun` 数量，非零时抛 `TemplateInUse`（409，`template_in_use`）。
- 新：直接 `get_template` + `session.delete` + `commit`，并在 docstring 说明运行记录保留的原因（`:588-599`）。`TemplateInUse` 类不再有调用方，一并删除。
- 实现思路：把「删除模板」与「删除评测」彻底分开；运行表本来就没有外键，来源字段允许悬空。

**检视发现**：`template_briefs()` 的「missing ids stay unresolved」注释（`:816-824`）早就预想了模板被删除后的行为，本次实现与既有读侧契约一致，没有新增读侧分支。

### 9.5 `tests/backend/test_eval_templates.py`（M）

**职责一句话**：模板 API 回归；新增删除停用模板后历史运行保留的用例。

**变更代码块分析**

- 旧：launch 幂等测试末尾用 `client.delete` 断言有运行模板返回 409 `template_in_use`。
- 新：该断言移出；新增 `test_delete_disabled_template_preserves_started_runs`（`:633-663`），先启动、再停用、再删除，断言模板 404、`EvalRun` 仍在且 `template_id` / `template_version` 保留、评测详情 200 且 `template` 为 `null`。
- 实现思路：把「删除不删历史」从注释提升为可执行契约。

**检视发现**：无。
