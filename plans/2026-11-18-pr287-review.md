## §1 一页速览

一句话：把轨迹页顶部那个没有前缀、容易被误读为 sessionId 的 attempt id，拆成 `attemptId:` 与主 Agent 根会话原生 `sessionId:` 两行，并明确空态与超长截断。

比喻：原来的顶部标识像一张只写了姓的名片；这次把“名”（attempt）和“姓”（主 Agent 会话）分两行印清楚，查档案时不会再拿别人的姓去对号。

| 交付块 | 结果 |
|---|---|
| 后端取数 | attempt payload 返回 `main_session_id`，复用 `trace_sessions.main_session_id` |
| 前端标识 | 两行 10px 等宽字体，62px 标签列，`attemptId:` / `sessionId:` |
| 空态 | `sessionId:` 为 `—`，悬停解释“未解析到主 Agent 会话…” |
| 长值 | `max-width: 330px` + ellipsis，`title` 携带完整值 |
| 响应式 | 顶部允许 flex-wrap；900px 下摘要换行，不压在标识上 |
| 测试 | 后端 1 个新用例 + 现有断言；前端 3 个模型用例 |

验证基线：`npm test` 105 passed；`pytest tests/backend` 全绿；`npm run build` 通过；`npm run verify:flow`、`npm run verify:docs` 通过。生产截图基线 `main@170591e`，改动分支 `9b0b73e`（rebase 前 `361da39`，内容相同），同 1600×1000、浅色主题、同一 seeded attempt。

## §2 架构导览

### 2.1 后端取数与语义来源

`backend/app/services/trace_queries.py:495` 在组装 attempt 时调用 `resolve_main_session_id`。该函数来自 `backend/app/services/trace_sessions.py:13`，与用例明细 `workbench.py`、自进化上报共享同一取数规则：`parent_session_id IS NULL`、`status != unlinked`，按 `ordinal, id` 取第一个根会话的 `native_session_id`；空串归一为 `None`。

这里刻意再查一次库，而不是从已加载的 `sessions` 列表里挑：规则只有一份实现，避免页面与上报口径漂移。每次 attempt trace 请求只多一次按 attempt id 的索引查询，不随 session/span 数增长。

### 2.2 前端解析与展示

`web/src/api/traces.ts:40` 为 `TraceAttempt` 增加 `main_session_id: string | null`，`parseAttempt` 在 `:172` 用现有 `stringValue` 归一，缺字段时回退 `null`，因此旧后端响应或滚动发布期间不会抛错。

`web/src/features/traces/traceModel.ts:7` 定义空态提示文案与 `TraceIdentifierLine`；`:22` 的 `traceIdentifiers` 把 attempt id 与主会话 id 归一为两行：attempt 缺失时沿用“尚未生成 attempt”，session 缺失时为 `—`，并给出悬停标题。把文案与空态放在纯函数里，是为了在没有 React 测试依赖的本仓库里仍能被 `node --test` 覆盖。

`web/src/pages/TracePage.tsx:2320` 计算标识，`:2514` 渲染 `.trace-ident` 两行。session 行只在空态时带 `empty` class，`title` 均为完整值或空态原因。`web/src/styles/trace-viewer.css:202` 到 `:232` 与原型一致：纵向两行、标签固定 62px、值 10px 等宽、`max-width: 330px` 截断、`white-space: nowrap`。

### 2.3 文档与流程

## §3 数据流走查

1. 用户打开 `/evals/:runId/cases/:caseRunId/trace`，`TracePage` 用 URL 里的 attempt 调 `GET /api/v1/eval-case-runs/:id/trace`。
2. `trace_queries.attempt_trace` 校验 case run/tenant/project，取 attempt、files、sessions，再解析 `main_session_id` 写进 attempt。
3. 前端 `parseAttemptTrace` → `parseAttempt` 得到 `main_session_id`；`traceIdentifiers(attempt, main_session_id)` 生成两行。
4. 左侧会话切换只改 URL 的 `session`/`span`，不改 attempt，因此 `main_session_id` 不变。实测 root → child 切换后两行值均保持不变。
5. 无 trace 的 failed attempt 仍走同一页面：attempt 存在、sessions 为空，`sessionId:` 为 `—`，原有“该 attempt 没有可用轨迹”告警保留。

## §6 讨论点

### 6.1 额外查询 vs 复用已加载 sessions

- **位置**：`backend/app/services/trace_queries.py:495`
- **现象**：attempt_trace 已经加载 sessions，仍调用 `main_session_id` 再查一次。
- **问题**：是否有必要多一次查询？
- **预判**：值得。主会话规则同时服务上报与用例明细；从已加载列表另写一份挑选逻辑会制造第二套口径。单 attempt 页面一次查询可忽略。
- **结论**：接受，不改。

### 6.2 空态 class 没有对应样式

- **位置**：`web/src/pages/TracePage.tsx:2531`
- **现象**：空态 session 值带 `empty` class，但 CSS 没有 `.trace-ident-value.empty` 规则。
- **问题**：dead class 是否应删除或补样式？
- **预判**：原型同样保留该 class，当前视觉由 `—` 与 `title` 表达；补颜色会让空态与普通值产生未确认的视觉差异。
- **结论**：保留，与原型一致；等视觉需要再定。

### 6.3 1024px 下摘要越界是既有现象

- **位置**：`web/src/styles/trace-viewer.css:202`、`:234`
- **现象**：1024px 下 `.trace-summary` 的 right 超过 viewport（文档横向滚动），900px 时摘要换到下一行。
- **问题**：本次标识块是否造成拥挤？
- **预判**：不是本次引入。改动前后同一视口下 `document.scrollWidth` 均为 1080，摘要位置一致；900px 下标识与摘要无重叠，符合 issue 的“窄屏允许换行”。
- **结论**：不在本 PR 修；若后续统一处理窄屏横向滚动，另开 issue。

## §9 文件级代码分析

### 9.1 `backend/app/services/trace_queries.py`

- 职责：attempt 级轨迹查询与响应组装。
- 变更形态：M。前身在 attempt 对象里只输出 id/status/时间/错误。
- 依赖解读：`trace_sessions.main_session_id` 是本仓库自有的只读查询 helper，不是第三方包；它把“主 Agent 根会话”的定义收口到一处。
- 旧 → 新：旧代码没有主会话字段；新代码在 attempt 字典中追加 `main_session_id`。这样前端无需从 session 树里猜，也不会跟随选中会话。
- 实现思路：取值走共享 helper，空值由 helper 归一为 `None`。
- 检视发现：查询次数 +1（见 6.1），接受。

### 9.2 `web/src/api/traces.ts`

- 职责：控制面响应到前端类型的解析与校验。
- 变更形态：M。
- 旧 → 新：`TraceAttempt` 增加 `main_session_id`；`parseAttempt` 增加一行 `stringValue`。
- 实现思路：沿用现有宽松解析，字段缺失为 `null`，保持向后兼容。
- 检视发现：无。

### 9.3 `web/src/features/traces/traceModel.ts`

- 职责：轨迹页纯数据模型。
- 变更形态：M。
- 旧 → 新：新增文案常量、两行标识类型与 `traceIdentifiers`。
- 实现思路：把“标签固定、值可空、title 回退”的规则从 JSX 移到可测试的纯函数；attempt id 与 session id 都先 trim，空白视为缺失。
- 检视发现：无；空态 `empty` 字段供渲染层附加 class。

### 9.4 `web/src/pages/TracePage.tsx`

- 职责：轨迹页数据装配与三栏渲染。
- 变更形态：M。
- 旧 → 新：旧的单个 `<span class="small muted mono">{attempt?.id ?? "尚未生成 attempt"}</span>` 换成两行 `.trace-ident`。
- 实现思路：`identifiers` 在 `trace` 数据就绪后计算；渲染只消费模型，不在 JSX 里做空值判断。`title` 用 `?? undefined` 避免 React 把 null 渲染成字符串。
- 检视发现：无。

### 9.5 `web/src/styles/trace-viewer.css`

- 职责：轨迹查看器样式。
- 变更形态：M。
- 旧 → 新：新增 `.trace-ident` / `.trace-ident-line` / `.trace-ident-label` / `.trace-ident-value`。
- 实现思路：flex 纵向两行、baseline 对齐、标签不收缩、值可收缩并 ellipsis；`max-width: 330px` 控制顶栏占用。与原型逐条对应。
- 检视发现：空态 class 暂无规则（见 6.2）。
