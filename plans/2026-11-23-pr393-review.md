## §2 架构导览

### 2.1 组件接口：从「只读展示」变成「带动作的弹窗」

`web/src/components/TemplateApiModal.tsx:9-19` 新增必填 `onLaunch: () => void`。组件仍是受控展示组件：`template` 为空直接返回 `null`，不持有权限或请求状态；`open`/`onClose` 由页面控制。`MethodBadge`（`TemplateApiModal.tsx:5-7`）是一个只在本地使用的 6 行小函数，把 `"GET" | "POST"` 渲染成带类名的 `span`。

标题区（`TemplateApiModal.tsx:25-32`）从字符串「模板接口」换成两块：主标题 + 副标题（模板名 + 三个执行接口）。这与原型 `prototype/app.js:1402-1408` 的 `modal({ title, subtitle, wide })` 结构一一对应；副标题里不再出现鉴权说明。

### 2.2 高度与固定页脚：antd Modal 的 flex 链

这是本次最核心的机制，三层配合才成立：

1. `web/src/styles/templates.css:183-188` 把 `.ant-modal-content` 变成 `display:flex; flex-direction:column; max-height:calc(100vh - 48px); padding:0`。
2. `templates.css:190-210` 让 header 和 footer `flex: 0 0 auto`，body `flex: 1 1 auto; min-height: 0; overflow-y: auto`。
3. antd v5.29.3 在 `centered` 模式下把 `.ant-modal` 设为 `top:0; display:inline-block; padding-bottom:0`（`web/node_modules/antd/es/modal/style/index.js:64-90`），所以 `.ant-modal` 自身没有高度，`max-height` 落在 content 上就能真正封顶。

关键在 `min-height: 0`：flex 子项的自动最小尺寸默认为内容的 min-content 高度；不写这行，正文会坚持按内容撑开，页脚被顶出弹窗外。写了之后，正文吸收「弹窗封顶高度 − 标题 − 页脚」的差额并自己滚动。实测 1500×837 下正文 clientHeight≈650、scrollHeight≈822，滚到底部后页脚与弹窗底边不动；1500 和 1200 两档弹窗都是 760×789、top=24，正是 `(837−789)/2`，说明 `max-height` 与 `centered` 的组合按预期生效。

代价与边界见 §6 D2：`100vh` 在移动端浏览器包含地址栏区域，真机上可能仍把页脚推到可视区外；这是桌面优先实现的常见取舍，本 PR 的验收视口都是桌面 headless。

### 2.3 横向溢出：`min-width: 0` 是断行的开关

原来的问题不是「代码块不会换行」，而是「代码块按 `pre` 的固有宽度把父级撑宽」：`templates.css` 旧版 `.template-api-code` 只有 `overflow-x: auto`，没有 `pre-wrap`；长 curl 的固有宽度 804px，直接把整项和正文撑到 834px。

新实现分三层拆解：

- **代码块**：`templates.css:319-332` 加 `max-width:100%`、`white-space: pre-wrap`、`overflow-wrap: anywhere`。`pre-wrap` 保留换行与缩进，`anywhere` 负责在 URL 这种没有空格的连续串里强制断点；`overflow-x:auto` 仅作兜底。实测修改后代码块 690px，curl 的 URL 在 `8192-` 后折到第二行，共 5 行（修改前 804px、不折行）。
- **路径行**：`templates.css:279-289` 给 `.template-api-head` 和其中的 `code` 加 `min-width:0`，并保留 `overflow-wrap:anywhere`。否则 flex 行里 `code` 的 min-content 会把行撑宽，路径不会折行。
- **列表与条目**：`templates.css:265-277` 给 `.template-api-list`、`.template-api-item` 加 `min-width:0`。这样 grid/flex 的自动最小尺寸不会再被长 UUID/长路径抬高，条目宽度跟随正文而不是内容。

一句话：`pre-wrap + anywhere` 决定「可以断」，`min-width: 0` 决定「父级允许它断」。两者缺一，长 curl 或长路径仍会顶破弹窗。

### 2.4 三列摘要与省略号

`templates.css:230-239` 用 `grid-template-columns: repeat(3, minmax(0, 1fr))`、`gap: 10px`；`templates.css:241-246` 给每列加 `min-width:0` 并改成纵向排列；`templates.css:248-259` 给 `code` 和 `.template-api-summary-value` 加 `overflow:hidden; white-space:nowrap; text-overflow:ellipsis`。

省略号能生效有两个前提：其一，三列的 grid 轨道用 `minmax(0, 1fr)`，轨道最小宽度是 0；其二，列内的 `code` 是 flex 子项（父级 `display:flex; flex-direction:column`），被块级化后 `overflow` 才生效。计算值与实测一致：弹窗 760 − 正文内边距 40 − 摘要边框 2 − 摘要内边距 28 − 两处 gap 20 = 670，三列各 223.3px；PR 记 223px，原型 222.7px。

### 2.5 方法标签与副标题去重

旧实现 `web/src/components/TemplateApiModal.tsx`（base 版）用 `<Tag color={method === "POST" ? "blue" : "default"}>`：GET 是 antd 默认灰、POST 是蓝。新实现自绘 `span.template-api-method`（`templates.css:291-305`）基础态就是原型 GET 蓝，`.post`（`templates.css:307-311`）覆盖为绿。像素取样确认生产截图与原型截图都出现 `#1768c5` 与 `#0b7b4b`，与 PR 声明完全一致。

副标题去重的做法是「搬走」而不是「删掉」：鉴权说明从正文首段搬到摘要第三列（`TemplateApiModal.tsx:61-64`，文案「会话 Cookie；启动需管理员权限」），头部只留模板名与接口用途。这与原型 `prototype/app.js:1366-1370` 的 `api-summary` 第三列一致。

### 2.6 页脚与启动接线

列表页（`web/src/pages/EvalTemplatesPage.tsx:364-373`）与详情页（`web/src/pages/EvalTemplateDetailPage.tsx:411-419`）都把 `onLaunch` 实现成「关接口弹窗，开启动确认弹窗」。列表页多一个 `if (!apiTarget) return;` 守卫，因为 `apiTarget` 可能为 `null`。启动确认弹窗本身有权限/启用态兜底：`web/src/components/TemplateLaunchModal.tsx:77` 的「确认启动」在 `!template.enabled || !canLaunch` 时禁用，并在 `:148-160` 给出「模板已停用 / 当前账号没有启动权限」的 Alert；后端 `backend/app/api/eval_templates.py:235-241` 的 launch 端点也要求 `require_admin`。

问题也在这里：接口弹窗页脚的主按钮没有接同样的约束，见 §6 D1。

## §3 数据流走查

以列表页管理员打开一个 36 位 UUID 模板为例：

1. 点击行内「接口」（`web/src/pages/EvalTemplatesPage.tsx:212-214`）→ `setApiTarget(row)`；`TemplateApiModal` 收到该模板快照。
2. 弹窗渲染（`web/src/components/TemplateApiModal.tsx:23-123`）：`base = window.location.origin`，摘要三列显示 Base URL、模板 ID、鉴权；四个接口项依次渲染 GET 列表、POST 启动、GET 状态、GET 结果。
3. 内容高度超过 `100vh − 48px`：`.ant-modal-content` 封顶 789px，正文（`templates.css:197-202`）变为滚动容器；标题与页脚留在原位。1500×837 实测 top=24、bottom=813。
4. 点击页脚「一键启动」（`TemplateApiModal.tsx:41-50`）→ 列表页 `onLaunch`（`EvalTemplatesPage.tsx:368-372`）先 `setApiTarget(null)` 关接口弹窗，再 `setLaunchTarget(apiTarget)` 开启动确认弹窗；两个状态在同一次事件里批处理，用户看到的是「一个弹窗换成另一个」。

7. 相反路径（停用模板 / 非管理员）：所有页面级启动按钮都是禁用的（列表 `:228-236`、详情 `:189-196`、`:303-310`），但接口弹窗页脚「一键启动」仍可点击，点开后启动确认弹窗的「确认启动」是禁用的并显示原因。这个分支是 §6 D1 的讨论对象。
8. 原型侧同一条路径：`prototype/app.js:1402-1412` 的 `openTemplateApi` 用 `modal({ wide:true, footer: 关闭/一键启动 })`，页脚按钮 `data-action="template-launch"` 直接复用启动确认。生产把「关一个、开一个」显式写出来，行为等价。

## §6 讨论点

### D1 页脚的「一键启动」没有跟随模板启用态和账号权限

- **位置**：`web/src/components/TemplateApiModal.tsx:37-50`；列表页接线 `web/src/pages/EvalTemplatesPage.tsx:364-373`（对照同页启动按钮 `:228-236`）；详情页接线 `web/src/pages/EvalTemplateDetailPage.tsx:411-419`（对照 `:189-196`、`:303-310`）；兜底 `web/src/components/TemplateLaunchModal.tsx:77`、`:146-160`；后端 `backend/app/api/eval_templates.py:241`。
- **现象**：接口弹窗的页脚主按钮永远是启用态。停用模板或非管理员点击后，只是打开启动确认弹窗，确认按钮是禁用的并显示「模板已停用 / 当前账号没有启动权限」。而页面上其它三个启动入口都在同样的条件下直接禁用。
- **问题**：一个当前无法完成的动作，是否应该以主按钮（`type="primary"`）的形态始终可点？对非管理员来说，弹窗摘要还写着「启动需管理员权限」，但右侧仍是一个醒目的蓝色「一键启动」，点了才知道不行。这算不算把权限提示做成了「先点击、再被拒」？
- **预判**：这不是安全问题——启动确认弹窗禁用、后端 `require_admin`、停用模板的 service 校验都在，链路不会被绕过；它是一致性和预期管理问题。原型没有角色概念，所以「永远可点」是忠实还原；但生产其它入口已经建立了「不可启动就禁用」的约定。建议给 `TemplateApiModal` 增加 `canLaunch` / `launchReason`（或直接传 `launchDisabled` + `title`），由两个页面把已有的 `!template.enabled || !isAdmin` 传进来，改动约 10 行；若产品更想要「先解释再拒绝」，至少把按钮降为次级并加 `title`，别让它看起来像可以完成的主操作。
- **结论**：本 PR 不改造，保留原型行为。issue #391 明确要求页脚提供「关闭 / 一键启动」；启动确认弹窗已有 `disabled` 与 Alert 兜底，后端也有 `require_admin`，权限与启用态没有被绕过。把 `canLaunch` / `launchReason` 注入只读展示组件会扩大组件接口并偏离原型；如后续要统一，可在两个页面传入 `launchDisabledReason`，同时用实时模板对象替换列表行快照。

### D2 antd Modal 的 flex + `max-height` 是否足够稳

- **位置**：`web/src/styles/templates.css:183-210`；antd 默认样式 `web/node_modules/antd/es/modal/style/index.js:64-90`、`:112-127`、`:161-193`。
- **现象**：`max-height` 写在 `.ant-modal-content` 上，借助 `centered` 时 `.ant-modal` 为无高度的 `inline-block` 才能封顶；正文用 `min-height:0` 才能成为滚动容器。当前 1500/1200 两档实测 760×789，与原型一致。
- **问题**：这套实现依赖 antd 的内部 DOM 类名（`.ant-modal-content/header/body/footer`）和 `centered` 的具体布局；未来 antd 升级若给 content 加高度或改 body 结构，页脚固定可能悄悄失效。另外 `calc(100vh - 48px)` 在移动端浏览器把地址栏也算进 `100vh`，真机上底部页脚仍可能落到可视区外。是否值得换成 `100dvh`，或改用 `styles` / `classNames` 官方 API 降低耦合？
- **预判**：当前实现是正确的标准「flex 子项滚动」写法，实测数据也支持；仓库里已经大量使用 antd 内部类名做局部覆盖，本 PR 并未引入新的耦合类型。`dvh` 是渐进增强，建议后续可加 `max-height: calc(100dvh - 48px)` 作为覆盖、保留 `vh` 兜底；不阻塞本 PR。若未来 antd 大版本升级，把「1500×837 弹窗 789 高、页脚可见」列入回归清单即可。
- **结论**：不阻塞本 PR。当前 flex + `min-height:0` + `centered` 的组合是标准写法且已实测；后续可加 `max-height: calc(100dvh - 48px)` 作为移动端渐进增强，并把该尺寸加入 antd 升级回归清单。

### D3 `min-width: 0`、三列省略号与 720px 回退

- **位置**：`web/src/styles/templates.css:230-332`、`:364-368`；DOM `web/src/components/TemplateApiModal.tsx:52-65`。
- **现象**：摘要三列各 223.3px，Base URL 与 36 位模板 ID 用 `nowrap + ellipsis`，完整值只放在 `title` 里；≤720px 时摘要变单列。原型没有这个断点，三列一直保持。721–792px 视口下（弹窗宽度仍在 760 与 100vw−32 之间）三列会缩到约 199–223px，模板 ID 在 10px 等宽字体下约 216px，开始省略。
- **问题**：720px 是按视口切的，不是按弹窗宽度切的；断点两侧的列宽并不连续，721px 时反而比 720px 更挤。是否应该改成与弹窗 760px 对齐的断点，或用容器查询直接按摘要容器宽度回退？另外，省略后的完整 URL/ID 只有 hover 的 `title` 能看到，触屏和键盘用户拿不到；是否需要复制按钮或 `aria-label`？
- **预判**：回退本身是 issue #391 明确要求的（「窄视口回退单列」），原型没有并不代表生产不该有；在没有横向溢出的前提下，720px 是保守且可用的选择。`min-width:0` 的三层设置是这次的关键修复，去掉任何一层，长 UUID/长路径都会重新顶宽。`title` 的触屏可达性是小瑕疵，不阻塞；若要更稳，可把断点改成 `760px` 或在 `.template-api-summary` 上做容器查询，并给模板 ID 补一个复制入口。
- **结论**：保留 720px 回退（issue 建议的窄视口单列），`title` 触屏可达性作为低优先后续项；不建议在无横向溢出的前提下扩大本 PR。

### D4 用 span 替换 antd Tag 的语义与一致性

- **位置**：`web/src/components/TemplateApiModal.tsx:5-7`、`:69`、`:79`、`:92`、`:101`；样式 `web/src/styles/templates.css:291-311`；对照详情页 mini 接口卡 `web/src/pages/EvalTemplateDetailPage.tsx:368-384`。
- **现象**：方法标签从 antd `Tag` 换成自绘 `span`。antd `Tag` 本身渲染的也是无 `role` 的 `span`，所以屏幕阅读器体验没有退化：读到的仍是「GET /api/v1/...」。颜色对比度实测 GET 5.01:1、POST 4.88:1，均过 WCAG AA 的 4.5:1；9px 字号与原型一致，但确实偏小。另一方面，详情页右侧的 mini 接口卡仍用 antd `Tag`（GET 灰、POST 蓝），同一个页面里出现了两套方法标签视觉。
- **问题**：自绘徽标带来了硬编码 hex、`.get` 类没有独立规则（GET 完全依赖基础类，若以后改基础类会静默变样）等维护成本；是否应该把 `MethodBadge` 提到 `TemplateBits` 之类共享位置，让 mini 卡也统一？还是明确「只有弹窗按原型、mini 卡保持 antd 默认」？
- **预判**：没有可访问性回归，颜色对比度也达标；`Tag` → `span` 是这次为对齐原型必须做的视觉替换。真正的遗留问题是同一页两套方法标签，以及 `.get` 空规则——都属于低优先级的一致性/可维护性，可以后续抽共享组件，不必阻塞本 PR。若抽共享组件，注意 mini 卡的尺寸和 `Tag` 的 `margin-inline-end` 与弹窗徽标不同，需要保留两种尺寸。
- **结论**：`Tag` → `span` 是原型对齐的必要替换，无无障碍回归；同一页两套方法标签作为低优先一致性债务，后续抽共享组件时再统一，不阻塞本 PR。

### 9.1 `web/src/components/TemplateApiModal.tsx`

**职责**：模板接口弹窗的展示组件；本次从「只读说明弹窗」变成「带固定页脚与启动动作的弹窗」。

变更后（新）：
```tsx

function MethodBadge({ method }: { method: "GET" | "POST" }) {
  return <span className={`template-api-method ${method.toLowerCase()}`}>{method}</span>;

<Modal
  open={open}
```

依赖解读：`antd` 是社区开源组件库，作为运行时依赖打进前端 bundle；`Modal` 在这里提供遮罩、焦点管理和 `centered` 布局，本文件只覆盖它的标题/页脚内容和少量类名。`Icon` 是仓库内部组件，`play` 图标与页面其它启动按钮一致。比喻：antd `Modal` 是成品门窗框，这次换了门牌（标题）、加了门帘（页脚），并把门框的限高交给 CSS。

实现思路：把「弹窗壳」交给 antd，把「壳内部的高度分配」交给 CSS（见 9.4），组件本身只负责内容与回调；`title` 用 ReactNode 装两行，避免再引入一个自定义 header 结构。

检视发现：

- 其余无发现：`if (!template) return null` 在 hooks 之前、`base` 的 SSR 守卫、`pre` 模板字符串的续行反斜杠都正确。
