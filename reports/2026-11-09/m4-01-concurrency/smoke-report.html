P1

SQLite 下 started 并发闸门被并发请求越过（冒烟首轮发现）

实际
4 个同时 started 的用例采样到 running=3/4，超过 cap=2。
预期
任意时刻 running ≤ effective_concurrency。
根因
check-then-act 无写锁；SQLite 忽略 SELECT ... FOR UPDATE，且事务读取到旧快照。
修复
在计数前 flush eval_run 写入（Postgres 行锁 / SQLite 写锁）串行化 started；修复后峰值恒为 2。
