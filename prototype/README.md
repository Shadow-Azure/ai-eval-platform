# AI Agent 评测平台 UI 原型

这是 M1-02 的单文件可交互 HTML 原型。原型不依赖后端、本地服务或网络资源，所有业务数据与状态切换都在浏览器本地完成。

## 运行

直接双击或用浏览器打开 `prototype/index.html`。CSS 与 JavaScript 已全部内联，可以通过 `file://` 运行。

源码仍拆分为 `template.html`、`styles.css` 和 `app.js` 便于维护。修改后重新生成单文件：

```sh
node prototype/build-standalone.mjs
```

演示账号为 `admin@acme.local`，密码 `eval-demo`。密码只做空值校验，不会发送到网络。

## 侧栏收起

- 侧栏底部「收起导航」在 236px 展开态与 72px 图标栏之间切换，状态保存在浏览器 `localStorage` 的 `ep.sidebar.collapsed`。
- 直接打开收起态：`prototype/index.html?sidebar=collapsed#/overview`；展开态可用 `?sidebar=expanded` 强制覆盖本地记忆。

## 主路径

1. 登录后从总览进入“数据集”，在通用目录中切换任务族、状态并翻页，再打开 SWE-bench Verified 详情。
2. 从数据集页进入“导入数据集”，依次完成来源、校验、生成版本三步。
3. 在“Agent 资产”查看 Git 仓库源；“添加 Git 资产源”中输入仓库、默认 Ref 和扫描路径，点击“自动扫描”后通过文件树勾选、移除或手动添加 Skill/Command/Subagent。
4. 在“模型凭据”查看掩码 Key；未授权角色不能查看或替换云账号密钥。
5. 在“资源池”查看 Mac mini 与 Linux Spot 的在线 Runner 数、最大并发和扩容状态。
6. 从“评测任务 → 发起评测”完成数据集、Agent/资产、模型/资源、确认四步；Git Ref 默认取资产源配置，也可在启动时修改，资产列表支持类型筛选、分页、全选和全部取消。
7. 在评测详情查看 SSE 实时进展、关键用例、结果快照与事件日志。
8. 打开“用例明细”页签，使用状态筛选、搜索和每页 20/50/100 条的分页；点击任意用例进入会话轨迹。
9. 在“交付流水线”查看 main 合入后的测试、镜像、数据库迁移、滚动更新与回滚状态。

右下角“原型评审”可以快速定位验收要求的边界状态。

## 状态矩阵

| 状态 | 原型位置 | 表达方式 |
|---|---|---|
| 空态 | 模型凭据搜索无结果 | 明确说明筛选条件并提供清除操作 |
| 加载中 | 数据集详情刷新 | 用例表骨架屏，保留页面结构和上下文 |
| 失败 | 评测详情 → 用例明细 → 失败筛选 | 状态标签、失败数量、实时事件和重试入口 |
| 无权限 | 资源池 → 资源连接 | 连接可被资源池引用，但密钥显示锁定态与权限申请 |
| 部分成功 | `eval-003` 完成 500/500，13 个失败 | 最终结果与失败数同时表达，避免伪装成全量成功 |
| 危险操作 | 取消运行中评测、回滚部署 | 说明不可逆范围、已产生费用和保留数据 |
| 凭据掩码 | 模型凭据、资源连接 | 只回显掩码，替换需要再次验证 |
| 容量不足 | 发起评测的资源步骤 | 显示在线数、池上限和排队风险 |
| 连接能力不匹配 | 新建资源池 → GitHub 私有 Runner | 供给模式下拉框中的竞价等云模式禁用，说明需要阿里云 ECS 连接，保存按钮禁用 |
| Ref 尚未解析 | 发起评测 → Agent / 资产 | 修改默认 Ref 后提示重新读取；未完成解析不能进入下一步 |
| 运行时前置缺失 | Agent 资产 → OpenSpec | 明确标出 CLI、初始化和生成型 Command 依赖 |
| Git 资产扫描 | 添加 Git 资产源 | 自动扫描后展示分页文件树，支持逐项勾选、移出和手动添加 |
| 轨迹降级 | 评测事件日志、原始轨迹 | 归一化失败时保留原始 JSONL/SQLite 入口 |

## 设计取舍

- 评测结果是“数据集驱动”的：页面读取数据集版本的指标定义，原型以解决率、Token/用例、成本/用例表达；新增评测集不需要改结果页骨架。
- 实时进展只显示关键用例样本；完整用例明细放到独立页签，默认每页 20 条并带状态计数，300 个用例显示 15 页。
- 进度卡与用例明细共用同一状态汇总：`submitted = resolved + unresolved + failed + running + queued`，失败数包含超时；解决率在运行中明确标注为“完成用例中的解决率”。
- 进度条按状态堆叠，绿色、灰色、蓝色、红色和浅蓝色分别对应已解决、未解决、运行中、失败/超时和排队，且与图例和结果分布保持一致。
- 结果分析的难度条形图按 Easy / Medium / Hard 分组，每根条使用与用例结果分布一致的状态色堆叠；完成趋势按日期和时间区间展示完成量，悬停或聚焦柱子可查看完成、解决、失败与平均耗时。
- 数据集目录是“适配器驱动”的：分页卡片读取类型名称、任务族、环境形态、版本、用例数、核心指标与接入状态，不把 SWE-bench 字段写进列表布局。
- 实时进展与最终结果共存：运行中的结果明确标记为快照，避免把部分聚合误认为最终成绩。
- 轨迹采用“左侧会话树 + 中间 waterfall + 右侧 span 属性”的三栏结构。主 Agent 与子 Agent 通过会话树和父 span 同时表达。
- Runner 容量始终以“在线数 / 池上限”呈现。一个自托管 Runner 默认只执行一个 job，因此 Mac mini 不会因为挂了多个标签而自动增加并发。
- 资源连接先于供给模式选择。供给器声明所需连接能力，原型在 GitHub 与阿里云连接之间切换时启用或禁用模式，后端仍需以 `connection_provider_mismatch` 做最终裁决。
- Agent 资产使用 Git 仓库作为唯一来源，保存可编辑的默认 Ref；发起评测时预填该 Ref，但允许覆盖，并在启动时固定到解析后的 commit 快照。
- 发起评测的资产列表覆盖完整扫描结果，通过分页浏览；“全选”作用于当前类型筛选下的所有页，“全部取消”清空当前资产源的全部选择。
- 添加资产源时先自动扫描 Git tree，再由人通过分页文件树确认最终清单；文件树不使用内部滚动，移出操作只影响当前导入，不修改远端仓库。
- 单租户身份在组织切换器中已经占位，但当前只展示默认组织，避免视觉复杂度超过 M1 范围。

## 遗留问题

以下问题不阻塞页面骨架，但需要在 M1-03 详细设计前确认：

1. 评测任务的“部分结果”是否允许对外分享，还是只在内部运行态展示。
2. 临时模型凭据在任务失败后是否立即销毁，还是保留到本次评测所有重试结束。
3. 轨迹消息内容默认展示到什么粒度，thinking 和工具原始输出是否需要按组织策略二次脱敏。
4. 结果对比基线是自动选择同配置最近一次评测，还是允许用户手动选择基线。
5. 资源连接的密钥权限是否只开放给组织 Owner，平台管理员是否仅能引用不能轮换。
6. 部署回滚是否允许平台管理员直接操作，还是必须经过二次审批。
